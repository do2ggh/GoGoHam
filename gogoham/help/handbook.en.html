1. Getting started

Installation

Easiest via your distribution's package repository (openSUSE, Fedora, Debian, Ubuntu, Arch): GoGoHam then stays up to date with your normal system update like any other program. The commands to copy are on GoGoHam's GitHub page (README, section "Installation"). Once the repository is added, you also find GoGoHam in the software centre (e.g. Discover or GNOME Software) – with description and pictures, under "Ham radio" or by searching for "contest" or "logger" (from 0.10.47.1).

From source: Run ./install.sh in the unpacked folder. The script installs PySide6 (with QtMultimedia for voice output), NumPy, Hamlib and SQLite, adds a “GoGoHam” entry to the start menu and asks whether it should allow the USB devices (radio cables, GPS, WinKeyer) for you – this works right away, without logging in again (see Allowing USB devices). Start it in a terminal with gogoham.

Beta AppImage: For testers, GoGoHam is also available as an AppImage - a single file to run, with no installation. It runs on almost any Linux. To remove it, simply delete the file.

Uninstalling

In a terminal: bash ~/.local/share/gogoham/uninstall.sh (from 0.8.23.5). The script asks first and removes the program, the start command, the menu entry and the icons. On request it also deletes settings and downloaded data (country file, map images …). Your logs in ~/GoGoHam are always kept.

Other programs keep working: if GoGoHam set up permanent rigctld or rotctld services, they are not removed but handed over as independent services (rigctld-4532.service etc.). QLog, WS & co. keep reaching the radio or rotator on the same port. If you no longer need them: systemctl --user disable --now rigctld-4532.service and delete the file in ~/.config/systemd/user/.

First start

On the very first start GoGoHam shows a welcome window. It tells you the best order for setting up – Open settings starts right away (at Operator), Later skips it. Important for operating:

  1. Connect to the internet if possible – then the clock is synchronised and GoGoHam can fetch data and updates.
  2. Operator: callsign and locator. This way new logs are already filled in, the companion programs (e.g. WS) are set up correctly, and on the live stick the time zone is right.
  3. Radio: so that frequency and band come by themselves.
  4. Data & updates → Download everything:
    • Country file (cty.dat) – countries, continents and zones for every prefix. Essential.
    • Super Check Partial (MASTER.SCP) – the call signs of active contest stations.
    • Flags – about 250 small pictures (approx. 1 MB), offline for good afterwards.

Everything else as needed: rotator, function keys, sound & announcements, online services, companion programs, appearance. If the country file is missing, the status bar says so.

All GoGoHam windows fit on the screen – also on laptops and with the taskbar. If space is short, the content scrolls; the buttons at the bottom always stay visible.

Everything can be downloaded again later under File → Settings → Data & updates – one by one or all at once with Download / update everything.

Settings → Operator (your details)

At the very top of the settings are your own details: callsign, name, locator, DOK (DARC/VFDB members only), year of first licence, licence class (e.g. A, E or N), date of birth, CQ and ITU zone (empty = from the callsign), club, address and e-mail (for the Cabrillo header). Everything is optional and is only stored on your computer.

  • When you create a new log, GoGoHam fills in everything the contest needs from these details – it works out your age from the date of birth. You can change everything in the log itself, e.g. a callsign with /P or a different locator; the details under “Operator” stay as they are.
  • The companion programs get callsign and locator from here (if a log is open, from the log).
  • The sections of the settings follow the order of setting up: Operator, Radio, Rotator, Function keys, Data & updates, Sound & announcements, Online services, Companion programs, Display (on the live stick finally USB stick).

Daily update at startup

Once a day GoGoHam checks for news at startup – while the splash screen is running (at most about 10 seconds, the rest continues in the background):

  • contest rules (changed files only),
  • country file (cty.dat and cty.csv) and MASTER.SCP – only if the file on the server is newer than yours,
  • DOK list,
  • flags – missing ones only, at most once a month,
  • the NASA map image of the grey line map – in each new month the matching image (about 30 MB, in the background; not while a contest is running).

Protection during a contest: while the contest of the open log is running, contest rules and country file stay unchanged – otherwise points could shift in the middle of the contest. GoGoHam catches up at the first start after the contest. MASTER.SCP and the DOK list only provide suggestions and are renewed during a contest as well.

Only what you already had is downloaded: if you never wanted the flags or MASTER.SCP, for example, you won't get them unasked. Without internet nothing happens; the message line at the bottom shows a short note. To switch it off: File → Settings → Data & updates → Update once a day at startup. The call history learns with every QSO anyway.

New GoGoHam version (from 0.9.3): also once a day at startup, GoGoHam asks GitHub whether there is a newer version. If so, the message line at the bottom shows e.g. "GoGoHam 0.9.5 has been released" – with the right way to get it: installed as a package of your distribution, it comes with your next system update; installed with install.sh or on the live stick, one click is enough (see Updating GoGoHam with one click). The hint appears only once per version and not while the contest of the open log is running. Check yourself at any time: Help → Check for a new version …; switch off: File → Settings → Data & updates → Check for a new GoGoHam version. It only reads, nothing about you is sent.

At start GoGoHam is empty and asks whether you want to continue with the log you used last (e.g. “CQ WW DX CW – cqww-cw-2026-DO2GGH.ggh (812 QSOs)”): Continue (preselected, so just Enter), New contest log … or No. So no old log keeps running unnoticed after a contest.

2. Creating a contest log

Log & Contest → New contest log (change later: Log & Contest → Log settings). There you choose the contest and fill in your details. For this there is a search field with a list below it (from 0.8.31.2): the list shows all contests and gets shorter with every letter you type, e.g. with "iar" only the IARU contests remain. The search covers the name, the short name and the Cabrillo name; spaces and hyphens do not matter. Use arrow up/down to choose in the list, Enter takes the contest and jumps to your own call, Esc clears the search field. Below the list GoGoHam shows how many contests it knows, while searching e.g. "6 of 47 contests". The window shows only what the chosen contest needs in the exchange – e.g. for IARU HF only “ITU zone / society”, for EU HF only the licence year. GoGoHam remembers what you entered once and suggests it again for the next matching log.

  • Own call sign and operator(s), if any
  • Own CQ zone – for Germany 14
  • Own locator, 6 characters (e.g. JN59me) – for beam heading and distance; in WW Digi only the 4-character part is sent automatically
  • Power in exchange – only for contests in which you send your power (ARRL DX as a DX station, e.g. 100 or KW). Empty = taken from “Category power” (High = KW, Low = 100, QRP = 5).
  • Own state/province – only for stations in the USA or Canada (e.g. CT, ON), for ARRL DX, CQ 160 and ARRL 10 m. For ARRL 160 m enter your ARRL/RAC section here (e.g. EMA).
  • ITU zone / society – for IARU HF, the ITU zone also for LZ DX and 9A DX. Empty = from the country file (Germany: 28). Society stations (e.g. DA0HQ) enter their abbreviation here, e.g. DARC.
  • Year of first licence – for the EU HF Championship: the year of your very first amateur radio licence (SWL licences count too), e.g. 1982. The last two digits are sent (“82”), also with club or special call signs. Without this year no EU HF log can be created.
  • Own DOK – for the DARC contests (WAG, 10 m, Christmas, Easter, training contests): the DOK of your local DARC club, e.g. B36, or a special DOK. Non-members and stations outside Germany leave the field empty – GoGoHam then sends NM.
  • Own oblast – only for stations in Russia in the Russian DX, e.g. MA.
  • Own IOTA reference – for the IOTA Contest, only if you operate from an island, e.g. EU-005. Leave it empty on the mainland.
  • Operator age – for the All Asian, e.g. 59. Empty = 01 (age not given).
  • Type of island station and island name – for the IOTA Contest, island stations only: “fixed station” (you live on the island) or “DXpedition”, plus the island name, e.g. Great Britain. GoGoHam writes both into the Cabrillo file.
  • Own code (host country) – for the country contests (OK/OM, HA, UBA, PACC, SP, LZ, 9A, YO, EA), only if you operate in the host country: your district, county, province or UBA section, e.g. BP or NH.
  • Membership number – for the AGCW Happy New Year Contest, AGCW members only, e.g. 2583. GoGoHam then sends 001/2583; empty = only the number. In the AGCW QRP Contest GoGoHam sends NM without a membership number.
  • Power class – for the AGCW QRP Contest (VLP, QRP, MP, QRO) and the QRP/QRP Party (A or B): a list with the classes of the rules. The class is sent and decides the points; the log cannot be created without a choice.
  • VHF section, transmit power (watts) and antenna – for the VHF/UHF contests: they go into the header of the EDI file (see VHF/UHF contests).
  • Categories for the Cabrillo file (operator, band, power, assisted, transmitter, overlay)
  • Name, e-mail, club, address and soapbox (optional, they go into the Cabrillo header)

Below the contest selection you see the rules status: when the rules in GoGoHam were last compared with the official contest rules. “Open official rules” shows them in your browser. If the status is older than one year, a warning appears – please check the rules before the contest.

Logs are stored in ~/GoGoHam/ as .ggh files. Every QSO is saved immediately – a crash or power cut costs at most the QSO you are typing.

3. Radio (CAT) and Hamlib

GoGoHam controls the radio via Hamlib rigctld. Under File → Settings → Radio you pick your radio from the complete Hamlib list (more than 300 models, taken directly from the installed Hamlib).

The tab shows up front only what most people need: profile, radio, port with Detect radio, baud rate, Test connection and Test PTT. Everything else – interface of older radios, WinKey, PTT via a control line, rigctld mode, own options – is behind the button Advanced settings … (from 0.8.22). Next to it a grey line shows what differs from the default there (e.g. “Advanced: CW via WinKey, PTT via RTS”) and what to enter in WS & co. – so nothing stays hidden unnoticed.

  1. Find the radio: type e.g. 9700, FT-991 or Kenwood – the list then shows only matching radios. “(Beta)” after the name means that Hamlib support is not quite mature yet.
  2. Below, GoGoHam shows what the radio can do according to Hamlib: bands, voice memory via CAT and CW via CAT.
  3. Port: the connected USB devices and USB-serial adapters are listed (“Search again” if you have just plugged in), plus built-in COM ports (/dev/ttyS…, only those that really exist) and Bluetooth adapters (/dev/rfcomm…). You can also type other names. Best use the fixed name from /dev/serial/by-id/. Some radios (e.g. Yaesu FT-991) show up with two ports – for CAT it is usually the first one (“Enhanced”, if00).
  4. Baud rate: only the values the radio supports according to Hamlib are offered; the highest is preselected. It must match the setting in the radio's menu.
  5. Detect radio (button next to the port): GoGoHam asks the radio "who are you?" and fills in radio, port and baud rate – you can change everything afterwards. If no port is selected, all connected ports are searched. Common Icom, Kenwood and Yaesu radios are recognised; for Elecraft, "Elecraft" is put into the search field and you pick the exact model. Only read commands are sent, nothing is ever transmitted. The fixed name of the port (/dev/serial/by-id/…) is always filled in – numbers like ttyUSB0 change when replugging. Yaesu radios with "CAT RTS = ON" (factory setting, e.g. FT-891) are asked a second time on the first port with the RTS line switched on if needed – there RTS only enables CAT, PTT is on the second port. The FT-991A is recognised from 0.8.24.1 and entered with the Hamlib model "FT-991" (Hamlib uses the same one for both). If GoGoHam finds several radios, it asks which one belongs to the profile; ports of other profiles are skipped.
    If a rigctld is already running for the port (e.g. as a system service), GoGoHam does not touch the port but checks whether the radio answers it. If so, GoGoHam takes over model, baud rate and port and selects "Use existing rigctld". If not (e.g. because a different radio is now plugged in at the same place), GoGoHam offers to take over control: the old rigctld is stopped (for a system service Linux asks for your password once), and profiles that used it get a permanent rigctld of their own from GoGoHam on the same port – WS etc. need no changes. No answer: is the radio switched on and its CAT interface enabled in the radio's menu? Older radios (e.g. FT-817/857/897, older Icom and Kenwood) do not report their name at all – then choose radio and baud rate by hand and use “Test connection” (see Older radios without USB). If you lack permission for the port, GoGoHam says so and gives the command.
  6. Phone and PC at the same time (GoGoHandy bridge, from 0.10.40): If the GoGoHandy PC bridge holds an Icom radio so the phone can operate too, GoGoHam automatically uses the bridge's virtual port – for detection, the connection test, its own rigctld and the background rigctld. The profile keeps the radio's fixed name; when the bridge is not running, everything goes directly to the radio as before. The bridge is never stopped. DTR/RTS lines (PTT or CW via a line) do not work through the bridge – so PTT on the same port goes via CAT by itself on Icom radios; set CW to CAT.
  7. GoGoHam, GoGoHome and GoGoHandy at the same time (from 0.10.43): exactly one rigctld runs per port and radio. If another service already holds the radio or the port (e.g. a rigctld handed over to the system or the service via the GoGoHandy bridge), GoGoHam does not create a second one but shares it – even on a different port; the status bar says which service is used. If such a service hangs without a radio (e.g. because it started before the bridge), “Detect” restarts it instead of switching it off. A service that runs via the bridge is never switched off.
  8. Test connection: reads frequency and mode once. Nothing is transmitted. If the radio is already connected, it is disconnected briefly and reconnected automatically afterwards.
  9. Test PTT: after a confirmation (antenna or dummy load connected, power suitable, frequency clear?) the radio transmits for 1 second and then returns to receive by itself – even if something goes wrong on the way, GoGoHam always switches PTT off again. If the radio reports its transmit state, GoGoHam tells you whether it really transmitted.

Radio profiles – every radio has its own rigctld

rigctld works like a telephone exchange: it is the only program holding the line to the radio, all other programs (GoGoHam, WS, a logging program …) “call in” – at a host and port, e.g. 127.0.0.1:4532. Every radio gets its own exchange with its own port (e.g. IC-7300 on 4532, IC-9700 on 4533).

Up to five profiles can be set up – slots 1 to 5 can be used in any order, e.g. profile 3 first and profile 1 later. All five slots are equal. A profile only tells GoGoHam which exchange to call. Switching therefore affects only GoGoHam – WS, logging programs etc. stay on their configured port and notice nothing.

The grey line next to Advanced settings … (and there the line “Other programs”) shows what to enter in WS, logging programs etc. (“Hamlib NET rigctl” with host:port of the profile).

For each profile you choose under Advanced settings … → rigctld. New profiles are set to “GoGoHam sets up rigctld permanently” (from 0.8.22.1) – then “Detect radio”, OK, and WS & co. can talk to the radio right away. Where that is not possible (see below), “GoGoHam starts rigctld itself” is the default. Existing profiles keep their setting.

  • GoGoHam starts rigctld itself – rigctld runs as long as GoGoHam is running (on the profile's port). For everybody who has not set up a service of their own.
  • GoGoHam sets up rigctld permanently – rigctld runs always in the background, from login onwards, even when GoGoHam is closed. So WS, logging programs etc. can talk to the radio at any time via the profile's port. When you click OK, GoGoHam creates a service just for your user (no password needed) that always uses the fixed name of the port. If the radio is unplugged, rigctld waits until it is back. Changing it is enough – GoGoHam adjusts the service. If you delete the profile or switch it, GoGoHam asks whether the rigctld should keep running for other programs (default: yes, from 0.8.23.5) – then it is handed over as an independent service and GoGoHam no longer touches it; otherwise it is removed. The same applies to the rotator. Beta AppImage: there this option is only offered if Hamlib is installed on the PC itself (e.g. Fedora: sudo dnf install hamlib) – the service then uses its rigctld.
  • Use an existing rigctld – e.g. a system service that is always running. GoGoHam only calls in and starts nothing.

System service replaced? If GoGoHam took over another rigctld service during “Detect radio”, other programs (logging programs, WS …) still expect a rigctld on that port at all times. If the profile there is set to “GoGoHam starts rigctld itself”, GoGoHam asks once when saving whether to set the rigctld up permanently instead (from 0.8.23.4) – otherwise these programs report e.g. an “Input/output error” while GoGoHam is closed.

GoGoHam never starts a second rigctld on a port that is already in use. If one is already running there, GoGoHam shares it and says so in the message line at the bottom.

GoGoHam starts with the profile you used last (from 0.8.31.1). Switching via Station → Radio profile or by clicking the CAT display at the top right therefore also applies the next time you start. If that radio is not connected then, the CAT display says "not connected". GoGoHam does not switch to another radio by itself; you choose it in the menu. For new users no radio is preset – the CAT display then says “CAT: no radio – click here”.

The CAT display shows the radio that really answers (rigctld is asked for it), e.g. “CAT: connected · IC-7300”. If it does not match the profile, it shows in orange e.g. “… IC-7300 – profile is “Dummy”!” – then the port in the profile is usually wrong.

Test connection in the radio window reads frequency and mode once (nothing is transmitted) and names the radio answering on the port.

The band selection at the top only shows bands on which the chosen radio can transmit (for the IC-9700 e.g. 2 m, 70 cm, 23 cm). With CAT switched off, all bands are available. If a radio cannot play voice memories or send CW via CAT according to Hamlib, GoGoHam says so when you press F1–F8 instead of silently doing nothing.

Radio over the network (LAN/WLAN)

Many newer radios are connected to the home network by LAN cable or WLAN. In Settings → Radio choose the matching entry under “Connected via”:

  • Network (LAN/WLAN) – Icom (e.g. IC-705, IC-7610, IC-9700, IC-905): GoGoHam speaks Icom's network remote control itself – no extra program needed. In the radio, switch on network remote control (Network Control) and create a user with password (Network User). In GoGoHam use “Search network” (or enter the address), enter user name and password, then “Test connection”. GoGoHam then provides the radio as a rigctld as usual – WSJT-X, fldigi & co. connect with “Hamlib NET rigctl” as before. With the tick “Audio over the network” a sound card of its own appears in the system (GoGoHam-…-Empfang / GoGoHam-…-Senden); GoGoHam enters it in WSJT-X and fldigi and uses it for the voice memories. All of this runs while GoGoHam is open. Important: Icom only obfuscates user name and password, it does not encrypt them – use it in your own network only, never openly on the internet.
  • Network (LAN/WLAN) – other makers: for radios Hamlib can control over the network itself (e.g. Elecraft K4, FlexRadio). Address and port are in the radio's manual.
  • Radio on another computer: the radio is cabled to another computer (e.g. a Raspberry Pi in the shack) running rigctld. “Search network” finds it in your own network (ports 4532–4536); it has to be reachable from outside (rigctld … -T 0.0.0.0).

Status: the Icom support is new (beta) and so far only tested against a simulated radio. Feedback with real radios is very welcome. Kenwood radios with LAN (TS-890S, TS-990S) need a login Hamlib cannot do yet – for now use them via the USB cable.

Your own rigctld service for a radio (optional)

If a rigctld should always run – even without GoGoHam, e.g. so that WS works on its own – it can be set up as a service. Example for a second radio (IC-9700, port 4533); please adapt the Hamlib number, port name, baud rate, TCP port and user name. File /etc/systemd/system/rigctld-ic9700.service (create it with sudo nano /etc/systemd/system/rigctld-ic9700.service):

[Unit]
Description=Hamlib rigctld IC-9700
After=network.target

[Service]
ExecStart=/usr/bin/rigctld -m 3081 -r /dev/serial/by-id/YOUR-DEVICE -s 38400 -t 4533
Restart=on-failure
User=YOUR-USER-NAME

[Install]
WantedBy=multi-user.target

Then enable it: sudo systemctl enable --now rigctld-ic9700.service
In GoGoHam choose “Use an existing rigctld” in the profile and enter port 4533.

Older radios without USB (interface, adapter)

Many radios have no USB socket but an RS-232, TTL or CI-V port. They are connected via an interface (level converter, CI-V cable such as the CT-17, Yaesu CAT cable) and usually a USB-serial adapter. That is no problem for GoGoHam – Hamlib knows very old radios too:

  1. Plug in the adapter, Search again, choose the port (the adapter appears as /dev/serial/by-id/usb-FTDI…, …Prolific…, …CH340… or similar; a built-in COM port as /dev/ttyS0).
  2. Try Detect radio. Older radios often do not report their name – then search the radio in the list and choose the baud rate as in the radio menu (old radios: often 4800 or 9600, some 1200).
  3. Test connection. If it fails, look under Advanced settings …:
  • Power for the interface: many simple interfaces draw their power from the DTR and/or RTS control lines of the port. If the interface manual says so, choose “Switch DTR and RTS on” (or only one of them). “Detect radio” and “Test connection” use this setting too. Caution: with other interfaces RTS or DTR switches the radio to transmit – then that line must not be on permanently. Hence the red warning, and GoGoHam refuses if the same line on the same port is also set as PTT.
  • CI-V address (Icom): leave empty = the model’s default (shown in grey, e.g. 94 for the IC-7300). Only enter one if the address was changed in the radio or several Icom radios share one CI-V cable – then each needs its own address. Two hex digits, e.g. 5E.
  • Frequency polling: with the polling interval set to automatic (default), GoGoHam measures on connecting how fast the radio answers and asks as often as possible – at most 50 times per second, less often with slow radios so the port stays free (e.g. for WS). The IC-7300 needs about 4 ms per query and is asked 50 times per second. The mode is read once per second. Your own value (20 to 2000 ms) is used instead of the measurement. Below the field you see what was measured on the connected radio. On connecting GoGoHam also sets the rigctld cache to 10 ms (otherwise Hamlib reports the old frequency for up to 1 second) – the frequency display and band map then follow the VFO smoothly.
  • For experts: further rigctld options, e.g. --set-conf=serial_handshake=None. They are appended to rigctld.

Permission: Linux does not simply let programs use serial ports. When installed from the package repository this is already taken care of. Otherwise the button “Set up permission …” appears when detecting or testing: one click on Allow and the system password are enough – it works right away (see Allowing USB devices). Where that is not possible, GoGoHam adds you to the group (Arch: uucp, Debian/Ubuntu: dialout). If you prefer to do it yourself, the window shows the command with your user name to select and a Copy command button (paste it in the terminal with Ctrl+Shift+V). Then log out and back in once.

So far only the IC-7300 via USB has been tested for real. For interfaces GoGoHam sets lines and addresses as Hamlib and the manufacturers describe – feedback with real older radios is very welcome (Help → Create bug report).

Sound card of the radio (for WS and fldigi)

Many radios have a built-in USB sound card (e.g. IC-7300, IC-705, FT-991A – usually “USB Audio CODEC”). Inside the radio it sits on the same USB hub as the CAT port. That is how GoGoHam finds out by itself which sound card belongs to which radio – even with several radios (directly via the sound system PipeWire/PulseAudio, no extra program needed). GoGoHam uses the same sound card for its own voice memories. Under Advanced settings … “Sound card of the radio” is therefore normally set to Automatic (detect via USB), with what was found shown below.

Some radios have no sound card of their own, e.g. the FT-891: its USB cable only carries the control commands. The audio is available at the DATA jack – for FT8 or RTTY you need an audio interface (e.g. Digirig, SignaLink). Select it here once; GoGoHam remembers it for this radio.

CW via WinKey and PTT via DTR/RTS (e.g. microHAM DXP)

Under Advanced settings … (Radio tab) there are two more lines per profile:

  • Send CW via: "Radio (via CAT)" (as before - the radio keys the text itself) or "WinKey (own port)". A WinKey (K1EL WinKeyer 2/3) is a separate CW keyer on its own port - e.g. a WinKeyer USB or the one built into the microHAM DXP. GoGoHam sends it the function keys, ESM and Auto-CQ, Esc stops, Page Up/Page Down changes the speed. The speed knob on the WinKey works too (10-50 WpM), the display at the bottom follows. If you touch the paddle, the WinKey stops at once and the ticker ends. Check WinKey only asks for the version - nothing is transmitted.
  • PTT (transmit): "CAT (command to the radio)" as before, or the DTR or RTS line of a port. Voice memories need this, for example, when the radio is keyed through an interface. Since 0.10.45 the line is switched by rigctld - GoGoHam does not open the port itself. So only one program uses the port per radio, and WSJT-X, fldigi, GoGoHome and GoGoHandy transmit over the same line by themselves with their setting "PTT via CAT". Test PTT also goes through rigctld. If GoGoHam shares the rigctld of another service (e.g. a handed-over one or one you created) that does not switch the line, GoGoHam asks once whether to add it there (from 0.10.46): on "Yes" it makes a backup (….gogoham-<time>.bak), adds --ptt-type and restarts the service briefly - but only if nobody is transmitting; for a system service it asks for your password. If a rigctld runs without a service (started by hand), GoGoHam only shows a note in the status bar: then add --ptt-type=DTR (or RTS) where that rigctld is started. For Icom radios with PTT on the same USB port GoGoHam transmits via CAT (CI-V) - Icom radios can always do that, and the GoGoHandy bridge stays undisturbed.
  • Transmit guard (from 0.10.46): if GoGoHam crashes or hangs while transmitting, the radio would otherwise stay on transmit - rigctld does not notice. So a small guard runs alongside GoGoHam: if GoGoHam is gone, it switches to receive at once; if GoGoHam does not respond for 10 seconds while transmitting, likewise (GoGoHam then says so in the status bar). It works for PTT via CAT and via DTR/RTS. If another program (e.g. WSJT-X) is transmitting, the guard leaves it alone. Nothing to set up.

microHAM DXP: With one USB cable the DXP appears as a sound card ("microHAM DXP Analog Audio ...") and as three ports (/dev/ttyACM...): CAT, FSK and WinKey. Set it up like this:

  1. Port (at the top) = CAT port of the DXP, baud rate as in the radio.
  2. Send CW via = WinKey, next to it the WinKey port of the DXP.
  3. PTT via DTR: in the DXP menu set "DTR = PTT" for one port (menu 1.2 CAT DTR, 1.3 WINKEY DTR or 1.4 FSK DTR) and choose exactly that port here. According to microHAM this is more reliable than PTT via CAT. Do not set the other DTR options in the DXP to PTT or CW.
  4. For your own voice recordings choose "microHAM DXP Analog Audio Output" as audio output.

Easier: "Detect radio". If a DXP is connected, GoGoHam recognises it by its USB ID and finds the three ports itself: first the WinKey (it is the only one that answers with its version number), then the radio behind the CAT port (it must be switched on). GoGoHam fills in port, radio, baud rate and "Send CW via: WinKey" - everything stays editable. PTT is not filled in, because the program cannot read which port has "DTR = PTT" in the DXP menu. Nothing is transmitted. GoGoHam never sends the CAT queries to the WinKey port - a WinKey would send them as CW. If you pick the WinKey port for CAT by mistake, GoGoHam tells you.

If ModemManager is running (it likes to grab new ttyACM devices and disturbs the DXP) or you are not allowed to use the ports, GoGoHam shows the matching commands to copy after detection. You run them yourself in a terminal; they ask for your password.

To be honest: the WinKey part is built from K1EL's public data sheet and tested with a simulated WinKey - not yet with a real DXP or WinKeyer. Feedback is welcome.

Rotator (from 0.8.23)

GoGoHam turns the beam via Hamlib rotctld – just like the radio via rigctld. Set it up under File → Settings → Rotator:

  1. Tick Control rotator, search the rotator or interface in the list (e.g. GS-232, ERC, SPID, Easycomm). Below it the model’s range is shown (e.g. −180…450°).
  2. Choose port and baud rate (as in the interface manual).
  3. Test connection – reads the heading once. The rotator never turns.

Rotator without a PC connection? Many controllers (Yaesu G-450, G-1000/G-1000DXC, G-2800, Kenpro, Hy-Gain/CDE Ham IV, T2X …) have no PC port of their own. For them there are interfaces that plug into the external control socket (Yaesu: “EXT CONTROL”) and connect to the PC via USB – e.g. Yaesu GS-232A/B, the ERC by DF9GR, the Arduino controller K3NG (mostly GS-232 compatible), Rotor-EZ/DCU-1 (Hy-Gain), Green Heron RT-21, ARS (EA4TX). In GoGoHam you then choose the interface, not the rotator. If other software with a rotctld port is already running (e.g. PstRotator), choose “Use an existing rotctld” under Advanced settings and enter its host/port.

As with the radio, GoGoHam sets up rotctld permanently by default (port 4540; other programs reach the rotator via “Hamlib NET rotctl” with 127.0.0.1:4540). Change it under Advanced settings ….

Operation:

  • Alt+R turns to the short path to the call in the entry field, Alt+Shift+R to the long path, Alt+S stops. The heading comes from the other station’s locator (VHF/UHF) or the country from the country file – as for the map.
  • Band map: right-click a spot → “Turn rotator: SP 312°” or “LP 132°”.
  • Turn automatically (tick on the Rotator tab, default off): once you have typed a call and stop typing for 1.5 seconds, the rotator turns to the short path – only if GoGoHam knows the heading and the rotator is not already (almost) there.
  • Status line: “Rotator: 287°”, while turning bold “Rotator: 287° → 312°”. Clicking it opens the rotator settings; the tooltip gives the reason if something is wrong.
  • Map (from 0.8.23.1): with the tick Beam above the map, an orange wedge from your location shows where the beam points – all the way to the antipode (where all great circles of one direction meet again). Its width is the antenna beamwidth, adjustable on the Rotator tab (default 30°; value from the data sheet, “half-power beamwidth”). The fill is strongest in the middle and fades out towards the edges – the strongest part is where the main energy goes; the beamwidth edges are finely dotted. While turning, the target is dashed next to it. A right click on the map – on an empty spot, a beacon or a spot – offers “Turn rotator: SP …° / LP …°”.
  • Rotator window (from 0.8.23.1, Window → Rotator, dockable): compass rose with the current heading (orange needle) and the target (blue, dashed). Clicking in the rose turns there, typing degrees and Enter or Turn does too; SP/LP turn to the call in the entry field, Stop stops. The window only operates – the rotator stays connected when it is closed. It can be opened at program start under Settings → Display.
  • Overlap: if the rotator has more than 360° (e.g. 450°), GoGoHam takes the shorter way from the current position. If a target is outside the range, GoGoHam says so and does not turn.

The rotator control has been tested with the Hamlib practice rotator (“Dummy”); feedback with real interfaces is very welcome (Help → Create bug report).

FT8 programs (WS …): GoGoHam only displays

As long as an FT8 program is running that sends data to GoGoHam via UDP, GoGoHam does not control the radio: band, mode and frequency are only displayed (selection greyed out), and GoGoHam transmits nothing (F1–F8, CW, Auto CQ blocked). At the top it says e.g. “CAT: IC-7300 · controlled by WS – display only”.

  • WS reports continuously (heartbeat every 15 s, status on every change) – GoGoHam notices the start after about one second.
  • When it quits, it signs off – GoGoHam takes over again immediately. If the sign-off is missing (crash), after 30 seconds without a heartbeat.
  • Programs that only send logged QSOs: 2 minutes display only after every QSO.
  • To switch this off: File → Settings → Companion programs, checkbox “Only display the radio …”.

If the FT8 program talks to the radio directly via the USB line (instead of via rigctld), GoGoHam points this out once. Better: in the FT8 program choose “Hamlib NET rigctl” under Settings → Radio and enter host:port of the rigctld as network server (e.g. 127.0.0.1:4532).

At the top right you see “CAT: connected” (green) and the frequency. Band and mode follow the radio automatically. Without CAT you set band and mode by hand in the header.

Bands

GoGoHam knows all HF bands from 160 to 10 m, plus 6 m, 4 m and 2 m as well as 70 cm, 23 cm, 13 cm, 9 cm, 6 cm and 3 cm (up to 10 GHz). In the band selection the centimetre bands appear as 70cm, 23cm etc. On export GoGoHam writes them the way the formats require: in the Cabrillo log as 432, 1.2G, 2.3G, 3.4G, 5.7G, 10G, in ADIF as 70CM, 23CM etc.

Tip: WS can use the same rigctld: in WS choose “Hamlib NET rigctl” as rig, network server 127.0.0.1:4532. Then the programs do not fight over the USB port.

5. Live scoring while typing

While you are still typing a call sign, the field directly below the call sign shows:

  • DUPE (red) – already worked on this band
  • NEW MULT (green) – e.g. “Zone 30, country VK”
  • OK (blue) – normal QSO
  • Does not count (orange) – wrong mode or WARC band, with the reason

After that you see the QSO points and the value for the total score, e.g. “3 pts · +766”. The value is how much your total score grows through this QSO: with a new multiplier the whole point total so far counts once more – that is why single QSOs can be worth several hundred points.

On the right you see the score per band, the total score and the rate (QSOs of the last 60 minutes and extrapolated from the last 10 minutes).

Worked on: Below the entry line there are boxes for the bands of the contest. They turn green if you have already worked the station you are typing on that band – so you see at a glance where it is still missing.

Message line and space weather (bottom)

At the very bottom of the window there are two lines:

  • Message line (top, room for two lines, coloured text): everything GoGoHam wants to tell you right now – QSY, messages from the radio (e.g. “voice memory 3 rejected”), errors, contest notes. Blue = note, orange = warning, red = error. After a few seconds the message disappears again. If there is nothing new, the ⚠ notes about the call sign you are typing are shown here (e.g. the count of band/mode changes). The live scoring (DUPE, NEW MULT …) stays directly below the call sign – where your eyes are.

6. Super Check Partial

From 3 characters on, the “Super Check Partial” window shows all matching call signs from MASTER.SCP and from your log, in alphabetical order:

  • red – already worked on this band (dupe)
  • blue – worked on another band
  • green – not worked yet

A double click takes over the call sign. The window can be detached and moved freely (or shown/hidden via Window → Super Check Partial). At program start it is only open if you have ticked it under File → Settings → Display → Open at program start (see Extra windows). If you make it wider, it spreads the call signs over several columns – side by side, row by row as you read. That way you see many matches without scrolling.

7. Call history

The call history remembers fixed details of stations: CQ and ITU zone, locator, DOK, US state, province, district, year licensed, member number, IOTA reference and name. Serial numbers, reports and power change all the time and are never remembered. When you type a call, GoGoHam suggests the known exchange (for "serial + DOK" and the like as a hint in the info box).

It writes itself (from 0.9.1): every logged QSO adds to it, permanently, in a file of its own (~/.local/share/gogoham/callhistory/gelernt.sqlite). Even if you delete a log, what was learned stays. Logs that were already in the folder ~/GoGoHam before 0.9.1 are read once at the first start – not again later, so deleted items do not come back. Practice QSOs (practice mode) are never learned. If you delete or edit a QSO, GoGoHam forgets or changes what it learned from it.

Where the details come from (the upper one wins):

  1. Learned – your QSOs, old logs you read in and values changed by hand. The newest entry always counts, so a one-off typo does not stick.
  2. Imported files in N1MM format (on the N1MM website under Downloads → Call History Files).
  3. The starter set that comes with GoGoHam (a few hundred stations from CQ WW logs).

Window Log & Contest → Call history …: type the start of a call to look it up. Change value … (or double-click) corrects a detail, Forget item deletes it. Learn from an old log … learns from earlier logs – Cabrillo files (.cbr/.log, also from other programs) or GoGoHam logs (.ggh). Nothing is taken from the header of a log (name, address, e-mail), only calls, fixed details and the date. Contests with a plain serial number (e.g. WPX) give nothing to learn. Import N1MM file … reads an N1MM file. Remove starter set takes out the bundled stations if you only want to work with your own logs or an N1MM file; Load starter set again brings them back.

Suggested values are always marked orange – copying the exchange is still a must, stations may move or operate portable.

8. Info box

To the right of the entry line: flag, country name and continent, below that the multiplier status (green = new on this band, grey = already worked, orange = ask for the zone or taken from the call history) and at the very bottom short path (SP) and long path (LP) with heading and distance.

In CQ WW and WPX the centre of the country is used – for large countries (W, VE, UA9, VK) the heading can be 10–20° off. In WW Digi it is exact because the locator is part of the exchange. Without your own locator there is no heading.

9. Function keys and voice memories

File → Settings → Function keys. In SSB, F1–F8 play either the radio's voice memories (on the IC-7300 recorded under VOICE) or – from 0.8.11 – your own recordings in GoGoHam (see Voice output). You choose this at the top of the tab under “SSB messages come from”. In CW they send messages via the radio or a WinKey; placeholders: {MYCALL}, {CALL}, {EXCH}, {RST}. Function keys need a CAT connection to the radio (CW via WinKey also works without).

CW speed

In CW you set the speed with Page ↑ (faster) and Page ↓ (slower), 2 WPM per step. GoGoHam only changes the setting on the radio – nothing is transmitted. The current speed is shown at the bottom in the status bar (“CW 30 WPM”); if you turn the knob on the radio yourself, the display follows within a few seconds. While an FT8 program is active, GoGoHam changes nothing. If a radio cannot report its speed via CAT, a note appears. With a WinKey the WinKey speed applies.

What is being sent

To the right of the “Worked on:” boxes GoGoHam shows what is going out – for F1–F8, “Enter sends” and Auto CQ:

  • CW: the text letter by letter. Sent letters are bold, the current letter has a blue background, what is still to come is grey. The radio does not report where it is – GoGoHam calculates it from the speed, so small deviations are possible. If GoGoHam does not know the speed yet (e.g. right after switching to CW), the text is just shown, without marking.
  • SSB: briefly the voice memory, e.g. “▶ Voice memory 1 (CQ)”. With own recordings it shows what is being said, e.g. “▶ DL1ABC 59 001” – until the message has finished.

Esc stops sending and the display disappears at once. Otherwise it disappears by itself a few seconds after the end.

Enter sends (ESM) – Run and S&P

With “Enter sends” (button ESM next to the function keys) you press almost only Enter: GoGoHam recognises where you are in the QSO and sends the matching function key. Off by default – when switched on, Enter really transmits.

The button next to it shows the operating mode: Run (you call CQ) or S&P (you search and answer). Switch with Ctrl+Tab or by clicking.

If the radio rejects a voice memory – usually because nothing is recorded in that slot yet – GoGoHam shows this in the message line at the bottom. On the IC-7300 you record the memories with the VOICE button.

Voice output in your own voice

Instead of the radio's voice memories, GoGoHam can send your messages itself through the radio's sound card – and build call signs and numbers from individually recorded letters and digits. Everyone records their own voice; no voice is shipped with the program. Recording and playback run entirely inside GoGoHam, without any other programs.

Setting it up (File → Settings → Sound & announcements → Voice recordings)
Everything on this tab – recordings, devices, tone, transmit level – is saved immediately, even if you close the settings window with “Cancel”.

  1. Choose devices: your microphone, the device for listening (headphones or speakers) and the radio's sound card. GoGoHam usually finds that one by itself – just as for WS and fldigi (see Sound card of the radio); it then shows “Automatic: …” and follows the radio profile. Only if nothing is found (e.g. FT-891 with a sound interface) you choose it once by hand. On the IC-7300 it is called “PCM2901 Audio Codec” – GoGoHam adds “(radio, e.g. IC-7300?)”. For an Icom over the network GoGoHam always uses its network sound card.
  2. Set the level: press “Check level” and speak. The bar follows your voice at once, the number (“Peak: −12 dB”) shows the loudest moment of the last 1.5 seconds. Peaks should be around −12 dB (green), never red. If the microphone is too quiet, raise the gain – it already works while recording.
  3. Record: pick an entry in the list, “● Record”, speak, “■ Stop”. The list then moves on to the next entry – so you can go through A to Z and 0 to 9 quickly. To record:
    • fixed messages: CQ call, thank you, QRZ?, please repeat, number?, call? and four own messages,
    • optionally your own call in one piece (sounds smoother; otherwise it is spelled),
    • the letters A–Z in the phonetic alphabet (Alfa, Bravo …), the digits 0–9 and the slash (“Stroke”, for /P).
  4. Listen – always via headphones or speakers, never via the radio. “Listen to message” plays a whole message, e.g. [CQ] {MYCALL} {MYCALL}.
  5. Switch on: on the Function keys tab, set “SSB messages come from” to “Own recordings in GoGoHam”.

What GoGoHam does by itself: silence at the start and end is cut – even if there is noise or the mouse click in it –, and all recordings are made equally loud – so a call sign built from pieces sounds even. Your raw recording stays saved unchanged.

Sound: three presets:

  • “Normal” – unchanged.
  • “Strong” (from 0.8.11.2) – the compromise between Normal and Contest: hum filter below about 120 Hz, less bass and less muddiness (low mids around 400 Hz), more presence. GoGoHam does not compress here itself – the radio’s speech processor does that (COMP on the IC-7300), otherwise the audio would be compressed twice.
  • “Contest” – narrow (300 Hz … 2.7 kHz), mids and highs raised, quiet syllables louder. Best with the radio’s speech processor switched off.

Plus sliders for bass, low mids, mid, treble and volume. If your voice sounds dull or “boxy”, lower the low mids; if it lacks punch, raise the treble.

Own profiles (from 0.8.11.3): choosing Normal, Strong or Contest sets the sliders to their base values. So that your own setting is not lost, save it with “Save as own profile …” to slot 1 or 2 and give it a name. Saved are the base type (Normal/Strong/Contest), all sound sliders and the volume. The profile then appears under “Preset” and can be selected again at any time. Saving to the same slot again overwrites it. The sound is applied on playback: listening sounds exactly like the transmission, and you can change it at any time without recording again.

Transmit level: how loud the audio goes to the radio – only on that path, listening is not affected. Set it with the radio's ALC meter, ideally into a dummy load.

IC-7300: for the audio from the USB sound card to be transmitted in SSB, menu MENU → SET → Connectors → MOD Input → DATA OFF MOD must be set to USB (or MIC,USB). With “MIC,USB” the microphone is on air as well – so keep quiet while a message plays.

Function key texts: under File → Settings → Function keys each key has a text in the column “SSB: own recordings”. Fixed messages go in square brackets: [CQ], [TU], [QRZ], [AGN] (please repeat), [NR] (number?), [CALLQ] (call?), [X1]–[X4] (own messages). Placeholders as in CW: {MYCALL}, {CALL}, {EXCH}, {RST}. Everything else is spelled out.

10. Auto CQ

Auto CQ plays your CQ call (F1) again and again automatically – handy when running and easy on your voice.

  • Start/stop: Ctrl+R or the “Auto CQ” button next to the function keys.
  • Timing: length of the CQ call + listening pause (default 3 s + 8 s = every 11 s), adjustable under File → Settings → Function keys.
  • Stops automatically as soon as you type a call sign, press Esc or use another function key.

With the radio's voice memories GoGoHam cannot tell when the radio has finished playing. So set the “Length of the CQ call” to the real length of your recording. With own recordings GoGoHam knows this itself: the listening pause starts as soon as the CQ call has ended.

11. Log table

Every contest shows the columns that matter for it by default (e.g. prefix in WPX, distance in WW Digi).

  • Order: drag a column header with the mouse to the desired position.
  • Show/hide: right-click a column header, tick or untick.
  • Width: the columns always fill exactly the width of the table – nothing disappears on the right under the score panel, which has a fixed place next to it. If the window gets narrower or wider, all columns change in the same proportion. Dragging only moves the border between two columns: what one gains, its right neighbour gives up – all others stay as they are. No column gets narrower than its title.
  • Restore default: in the same right-click menu.

The layout is remembered per type of contest. A double click on a QSO opens it for editing, Del deletes it (after asking). A right click on a QSO offers Edit, Delete and “Look up … on QRZ.com”, which opens the station’s QRZ.com page in your browser. Additions such as /P or a prefixed host country (EA8/DL1ABC) are left out, because QRZ.com only knows the home call. Which part is the call and which is only a country prefix GoGoHam tells from the country file – even when both parts are equally long, as in VP2E/W1AW (from 0.8.20).

12. Companion programs: WS and fldigi

Install and connect

Under File → Settings → Companion programs you find WS (FT8, FT4, FT2 …) and fldigi (RTTY, see RTTY with fldigi).

WS (“WS – Digital Mode Suite”, formerly WSJT-X Improved) is by Uwe Risse, DG2YCB. It has all the modes of WSJT-X and more, e.g. FT2, and a German user interface. The original WSJT-X is no longer included since 0.10.13; one that is already installed stays on the computer, GoGoHam just no longer sets it up. The same goes for JTDX since 0.10.17: there was no source from which it could be installed reliably on all systems. GoGoHam accepts logged QSOs from every program that reports them via UDP.

  • Install:
    • GoGoHam always fetches WS in the newest version straight from DG2YCB (SourceForge): on Debian, Ubuntu and the live stick the .deb package, on Fedora and openSUSE the .rpm package. GoGoHam checks the checksum, the required libraries come from the package sources (Linux asks for the password). On Arch/Garuda WS comes from the AUR (package wsjtx-improved, via paru or yay) – it is built on the computer, which takes a few minutes; a console window shows the progress.
    • fldigi always comes in the newest version from Flathub (com.w1hkj.fldigi) – the distributions' package sources often lag behind (Debian 13: 4.2.06, Flathub: 4.2.13). If flatpak is missing, GoGoHam installs it too. The first time, Flatpak also downloads a runtime – together about 1.4 GB of space (on the live stick in the data partition); installing itself only takes about a minute. An fldigi already installed from the package sources stays; GoGoHam then uses the one from Flathub – with its own settings under ~/.var/app/com.w1hkj.fldigi/.fldigi, which GoGoHam sets up at start as usual.
    • On older Debian/Ubuntu versions (e.g. Debian 12, Ubuntu 22.04, Linux Mint 21) GoGoHam automatically takes the variant DG2YCB builds for them (“boost1.74”, with the “AL” user interface) for WS.
    • If there is no way at all for your system (very rare distributions), the button Go to download page opens the program's official page.
  • Update: For WS and fldigi GoGoHam checks whether there is a newer version when you open this section. Then it says e.g. “installed 4.2.06 – new: 4.2.13” and the button reads Update.
  • Uninstall …: Next to every installed program there is this button. GoGoHam removes the program the same way it came (package manager or Flatpak; Linux asks for the password) – it asks you first. The program must be closed. Only the program itself is removed: if another program still needs it, uninstalling stops and GoGoHam tells you. For fldigi, Flatpak also removes runtimes that are no longer needed (frees up to a good 1 GB). Your settings and logs of the program are kept – after installing it again everything is as before. A program you built yourself or copied by hand is not removed by GoGoHam.
  • Transfer settings: GoGoHam enters the connection in the FT8 program: radio “Hamlib NET rigctl” with host and port of the active radio profile (Station → Radio profile), PTT via CAT and the UDP server for logged QSOs – plus your callsign and locator (from the open log, otherwise from Settings → Operator) and the sound card of the radio for receive and transmit (see Sound card of the radio). For WS GoGoHam also sets the language to the system language, unless you have already chosen one there. The other programs use the system language by themselves, as far as they come with a translation – otherwise they stay in English. Everything else you set in the program yourself. If GoGoHam finds no sound card (radio off, or a radio without one such as the FT-891), it tells you. After an install through GoGoHam this happens by itself; if the program is already set up, GoGoHam first shows what it would change and asks. Before that it makes a backup copy of the settings file (same folder, ending .gogoham-…bak). The program must be closed for this. The configuration the program is currently using is the one that gets set up.
  • If GoGoHam starts rigctld for this profile itself, the FT8 program reaches the radio only while GoGoHam is running – with “GoGoHam sets up rigctld permanently” (Radio → Advanced settings … → rigctld) also without GoGoHam.

By hand it works like this:

  1. In WS under Settings → Reporting set the UDP server to 127.0.0.1, port 2237.
  2. Under Advanced → Special operating activity enable WW Digi Contest.
  3. Share CAT: in WS “Hamlib NET rigctl”, 127.0.0.1:4532 (or the port of the radio profile).

As long as WS is running, GoGoHam only displays band and frequency and transmits nothing – see FT8 programs.

Every QSO you log in WS appears in GoGoHam immediately – with points by distance and field multiplier. From 0.10.43 GoGoHam sets WS up to send to the group 224.0.0.1 via the internal connection lo (settings UDP Server and Outgoing interfaces) – then GoGoHam, GoGoHome and e.g. a logging program (QLog, CQRLOG or KLog) all get every QSO at the same time, even without a network, and each of them can answer WS. If you still had 127.0.0.1, it is changed once; an address of your own stays.

fldigi can only send to 127.0.0.1 – there only one program ever gets a packet. If GoGoHam and GoGoHome run at the same time, whichever gets a QSO from fldigi passes it on to the other via the internal connection (from 0.10.43). Nothing changes in fldigi.

DARC FT4 Contest: the same settings, but enable nothing under Special operating activity: report and locator are exchanged as in a normal FT4 QSO. The DARC asks for the callsign without /P or /QRP and for real reports instead of 599.

RTTY with fldigi

In RTTY you operate with the proven free program fldigi; logging and scoring happen in GoGoHam – just like with WS. Just install fldigi once under File → Settings → Companion programs; there is nothing else to set up.

  • Starts by itself: When you open an RTTY contest log, GoGoHam starts fldigi – fully set up. When you switch logs or quit GoGoHam, GoGoHam quits fldigi again (only if GoGoHam started it). By hand: Station → Start digital program → fldigi.
  • Before every start GoGoHam enters in fldigi: the radio of the active profile (via rigctld) with PTT via CAT, the sound card of the radio (the same as under Sound & announcements → Voice recordings), callsign and locator from the log, RTTY with 45.45 baud and 170 Hz, the contest fields (callsign, RST, exchange, serial), passing every logged QSO to GoGoHam and contest macros on the first eight buttons: CQ · EXCH (callsign, 599, exchange twice) · TU+LOG · MYCALL · 599+LOG (S&P) · AGN · NR? · CALL?. GoGoHam sets the serial number. The first time, GoGoHam keeps fldigi's previous settings and macros as ….gogoham-original.bak in the folder ~/.fldigi.
  • Operating in fldigi: click a callsign in the receive text, use the macro buttons, log with TU+LOG or 599+LOG (or fldigi's log button). The QSO goes straight into GoGoHam – with points, multipliers and dupe check.
  • What fldigi cannot do alone: as soon as a callsign is in fldigi's call field, GoGoHam shows it with dupe, new multiplier and info box (country, distance …). Nothing is sent.
  • The radio switches to RTTY: with AFSK (tone via the sound card, default) to LSB data, with FSK to the RTTY mode. You choose FSK under Companion programs → RTTY (fldigi) with port and line (DTR or RTS). FSK needs its own port that is not already used for CAT – if in doubt, use AFSK.
  • Calibrate transmit level (Companion programs → RTTY (fldigi) → Calibrate transmit level …): after you agree, fldigi briefly sends a steady tone, GoGoHam raises the level in 3 dB steps and reads the radio's ALC. The loudest level at which the ALC does not move yet is used – so the signal stays clean. From then on fldigi uses it at every start. Only into a dummy load or on a clear frequency with low power; “Cancel” switches to receive at once. If the radio does not report ALC via Hamlib, calibration is not possible.
  • The frequency display in fldigi follows the radio with a small delay (about half a second) – that is fldigi's limit. The log uses the frequency from GoGoHam.

FT8/FT4 contests (e.g. WW Digi, DARC FT4) work the same way: GoGoHam starts the preferred FT8 program (Companion programs → Preferred FT8 program, otherwise the first one installed), checks the connection to GoGoHam first and quits it again at the end.

13. Export: Cabrillo, ADIF and EDI

Log & Contest → Export → Export log (Ctrl+E) asks for the format. The format the contest requires according to its rule file is preselected – Cabrillo on HF, EDI for the VHF/UHF contests. Cabrillo and ADIF are also available directly under Log & Contest → Export.

EDI is the log format of the VHF/UHF contests: GoGoHam writes one file per band (see VHF/UHF contests).

Cabrillo (Log & Contest → Export → Export Cabrillo) is the file you submit to the contest organiser. The log check runs automatically beforehand.

ADIF (Log & Contest → Export → Export ADIF) is for a logging program (e.g. QLog, CQRLOG or KLog), LoTW etc. and contains everything GoGoHam knows: country with DXCC name and number, continent, CQ and ITU zone, WPX prefix, contest ID, exchanges, your call sign, locator and zone – and, if set up, name and QTH.

Where does the log go?

After exporting as Cabrillo or EDI (for contests that require ADIF, also after ADIF), GoGoHam shows the window “Where does the log go?”: the exact submission route according to the rules, i.e. the e-mail address and/or the upload page, the deadline (worked out from the contest date, in UTC, with “… days left” or “⚠ passed”) and notes such as a required file name.

  • Open e-mail program (or click the address): your e-mail program opens with recipient and subject filled in. At the same time your file manager opens with the log file selected – just drag it into the e-mail as an attachment. GoGoHam cannot attach the file automatically because every e-mail program does that differently.
  • Open upload page (or click the link): the upload page opens in your browser, again together with the folder and the selected file.
  • Show folder: only the folder with the selected file.

The details are stored in the rule files (entry submit) and were checked against the rules (as of 11/2026). Where the route is not clearly confirmed, the window only shows the link to the rules. If your file manager cannot select a file, GoGoHam just opens the folder. On Linux GoGoHam opens the e-mail program via xdg-open, i.e. the program set under Default applications – no matter whether it is installed as a package, Flatpak or Snap.

14. Name and QTH (HamQTH / QRZ.com)

File → Settings → Online services → Name/QTH: enter your login for HamQTH (free) and/or QRZ.com (XML subscription required), choose the order and check with “Test login”. On ADIF export all call signs are looked up – if the first service finds nothing, the second one is asked. The results are stored in the log, so a second export is instant. The login data stays local (readable only by you).

15. Log check

Log & Contest → Check log – and automatically before the Cabrillo export. It finds:

  • call signs that are not in the SCP database and appear only once in the log – often copying errors
  • unknown prefixes, unusual zones, zones that differ from the call history
  • QSOs with wrong mode or band, faulty exchange
  • dupes (for information only) and, in WPX, gaps in the serial numbers sent

A double click on a hint opens the QSO for editing. Not every hint is an error – decide yourself and correct only what you know for sure.

16. Overview: multipliers and rate

Log & Contest → Overview opens a window with one tab per multiplier type:

  • Zones – all 40 CQ zones × bands, worked ones are green. So you see which zone you are still missing on 15 m.
  • Countries, Prefixes or Fields – everything worked, per band.
  • Rate – QSOs per hour as bars, coloured by band.

The window updates with every QSO and can stay open next to the main window.

17. Contest clock and operating time

At the top right you see UTC and below it the local time (from your PC's time zone). The log always uses UTC.

Below the score on the right is the countdown: “Starts in …” or “running · … left”. In WPX GoGoHam also counts the operating time for single operators: 36 of the 48 hours are allowed (overlay CLASSIC: 24), and a break only counts if no QSO is logged for at least 60 minutes. Shortly before the limit the display turns orange, above it red. The same applies in WAE (36 of 48 hours, breaks from 60 minutes); there a received QTC also counts as operating.

18. Live score

File → Settings → Online services → Live score: while the contest is running, GoGoHam sends your score to an online scoreboard every 2 minutes – so you can see live where you stand. The default target is contestonlinescore.com (create an account there, user name = call sign); the Score Distributor forwards to several scoreboards. The last status is shown at the bottom of the status bar.

19. Theme and language

File → Settings → Display → Theme: like system / Light / Dark / Franconia light / Franconia dark / Nightshift light / Nightshift dark – can be switched any time, independently of your PC's theme.

The two Franconia themes are red and white like the Franconian rake in the logo. Only the frames are red: menu bar, table headers, active tab and a line above the status bar. The working fields stay white (or dark), because red is GoGoHam's warning colour – a red “DUPE” still catches the eye immediately.

The two Nightshift themes (from 0.10.39) use colour gradients in amber (orange-yellow) and turquoise-blue. Nightshift dark has a night-blue background, Nightshift light a light one. The menu bar and the titles of the extra windows have an amber line at the bottom; table headers, the active tab and the main button of a window are amber with dark text. The window background has a faint glow, amber at the top left and blue at the bottom right. Amber is only used for frames, never in the working fields.

Easy to read with colour blindness, too: on the night blue GoGoHam uses brighter versions of the warning colours (dupe, multiplier, errors, hints), and a stronger orange in the light theme. Symbols and texts such as “DUPE” or “NEW MULT” stay the same. You recognise a selected row by the turquoise-blue bar at its left edge and a muted turquoise background. The dupe and multiplier colours are kept in the selected row as well.

In the Display tab you also set the font size of the entry line (takes effect after a restart). In the Data & updates tab, Download / update everything at the top fetches contest rules, country file, MASTER.SCP, DOK list, flags and both map images one after the other with a single click, with a tick also the natural voices (for announcements and SSB practice, off by default); finally it installs speech-dispatcher and asks for your password for that. The progress is shown below the button, and at the end a summary says what worked. Below it, as before, are the buttons for updating the country file, MASTER.SCP, flags, DOK list and contest rules, the call history import, the buttons for installing the speech output speech-dispatcher and for loading the natural voice Piper (both for the announcements), the checkbox for the automatic rules update and the backup interval.

Extra windows (Super Check Partial, band map, beacons, map, band openings)

All extra windows follow the same simple rule: window open = switched on, window closed = off. It does not matter how you open or close it – via the Window menu, via the small menu you get with a right click on a window, or with the X. Opening the band map connects GoGoHam to the DX cluster; closing it disconnects. The beacon display does the same with the Reverse Beacon Network; the map only calculates while it is open. Exception: if the open map shows cluster spots or beacons, that connection stays up for the map even with the band map or beacon display closed. Merely minimising the main window switches nothing off.

Which windows should be open right away at program start is ticked under File → Settings → Display → Open at program start. Default: none – you decide. The beacons only open at start if the log has 20, 15 or 10 m.

Start screen

On start GoGoHam shows its logo and a progress bar that sends GGH in Morse (--. --. ...., 14 wpm) – until everything is loaded, but at least once completely (just over 3 seconds). Below it you see what is being loaded. If GoGoHam needs to ask something at start (e.g. for a damaged log), the start screen steps aside meanwhile.

If you like, switch on the sidetone (650 Hz) under File → Settings → Display → Start screen. It only comes from your PC's speakers – the radio transmits nothing. Default: off.

The GoGoHam icon in the start menu, on the desktop and in the taskbar is set up by install.sh (without lettering in small sizes). If the old icon still shows up, log out and back in once.

Language

The user interface is available in twenty languages: German, English and – as beta, i.e. not yet reviewed by native speakers – Spanish, French, Portuguese, Russian, Indonesian, Italian, Danish, Swedish, Norwegian, Finnish, Polish, Czech, Slovak, Ukrainian, Dutch, Hungarian, Croatian and Turkish. The selection list is sorted alphabetically and scrolls. On first start the system language is used (if GoGoHam does not have it: English). Change it under File → Settings → Display → Sprache / Language; GoGoHam then asks whether it should restart right away – the log is saved and opened again. In English the country names come from the country file, numbers are written the English way (28,450.00 kHz). Cabrillo, ADIF, rule files and your logs do not depend on the language. Announcements (speech output): the Piper voices exist in German and English; in the other languages the system speech output speaks (speech-dispatcher or espeak-ng). This manual exists only in German and English: with a German user interface it appears in German, with all other languages in English.

More languages can be contributed without any programming knowledge: the translations are in gogoham/i18n/<language>.json – one line per text with the German original and the translation. If an entry is missing, the English text appears. Improvements to the beta translations are very welcome (Help → Create bug report).

20. Backups and repair

GoGoHam makes a backup when a log is opened and then every 10 minutes (if something has changed): ~/GoGoHam/Sicherungen/ (German for “backups”). The last 20 backups per log are kept.

Restore: Log & Contest → Restore backup, choose a backup. It is opened as a new log “…-wiederhergestellt” (“restored”); the old one stays unchanged.

Damaged log: if a log cannot be opened, GoGoHam offers to repair it, open another one or create a new one. Repairing creates a new file “…-repariert” (“repaired”) with everything that can be rescued; the original stays unchanged.

VHF/UHF contests (IARU Region 1 VHF and UHF/Microwaves)

Dates: 145 MHz on the first weekend in September, UHF/Microwaves (70 cm to 3 cm) on the first weekend in October, each Saturday 14:00 to Sunday 14:00 UTC.

Exchange: RS(T) + serial number + 6-character locator. The number starts again at 001 on every band – GoGoHam counts it per band itself. For the received exchange type number and locator into the exchange field, separated by a space, e.g. 12 JO20DB (JO20DB 12 works too). Your own locator must be entered with 6 characters under Log settings.

Points: 1 point per kilometre – the distance between the centres of the two locators, truncated, plus 1 (same locator = 1 point). GoGoHam calculates exactly according to the IARU rule (1 degree = 111.2 km). There are no multipliers; the score is the sum of the points. Each band is a separate result – the table on the right shows the points per band. The distance is shown in the info box and in the “km” log column.

Submitting the log: Log & Contest → Export → Export log writes the EDI format, one file per band (e.g. log_70cm.edi, log_23cm.edi). For the file header enter the VHF section (single, multi, low power, 6 hours), the transmit power in watts and the antenna under Log settings – the rules require this. Upload at the DARC via the log upload for VHF/UHF contests.

To be honest: I checked the EDI export against the official format description and its example – whether the evaluation software accepts it will only show with the first real submission. In the “6 hours” section GoGoHam scores all QSOs; the robot picks the 6 hours from the log itself. From 0.8.25 the contest clock shows your operating time “of 6:00 h” in this section (breaks only count from 2 hours).

DARC VHF contests (from 0.8.25)

The DARC VHF contests work just like the IARU VHF/UHF contests above: same exchange, 1 point per km, each station once per band (whatever the mode), one EDI file per band, upload at the DARC Contest Hub. All of them are in the contest calendar. Dates (always the first weekend of the month, UTC):

  • VHF/UHF/SHF contest in March, May and July: Saturday 14:00 to Sunday 13:59, 2 m up to more than 300 GHz. The classes Low Power (up to 100 W) and 6 hours exist only on 2 m and 70 cm.
  • VHF spring contest in April: Saturday 12:00 to 15:59, only 4 hours, at most 100 W for everyone.
  • Microwave contest in June: Saturday 14:00 to Sunday 13:59, from 23 cm only.
  • Marconi Memorial Contest in November: 2 m only, CW only. For the IARU ranking you must also submit the log to the IARU yourself; the DARC does not do this automatically.
  • VHF winter field day in February and VHF summer field day in August: portable only, with “/p” after the call, no power from the public mains, at most 15 W, no multi class.

Field day time windows: In the VHF field day each band is allowed only in its own time window. Winter: Saturday 09:00–10:59 23 cm, 11:00–13:29 13/9/6 cm, Sunday 09:00–10:59 70 cm, 11:00–12:59 2 m. Summer: Saturday 07:00–09:29 23 cm, 09:30–12:29 13/9/6 cm, Sunday 07:00–09:29 70 cm, 09:30–11:59 2 m. If you log outside the window, GoGoHam marks the QSO with “does not count” and names the correct time window. If your call has no “/p”, GoGoHam reminds you at every QSO. GoGoHam cannot check the 15 W; you have to take care of that yourself.

Bands from 24 GHz: In GoGoHam these bands are named after their frequency: 24, 47, 76, 122, 134, 245 GHz and “>300 GHz”. Trainee class: With a training call (DN1–DN8 or /T) select “Trainee” under Log settings → VHF section.

To be honest: The dates and time windows come from the 2026 rules. If the DARC changes them, a new rule file will follow. I have not tried with the DARC Contest Hub how the EDI file must name the bands from 24 GHz and the “Trainee” section. If the hub does not accept the file, choose the class by hand when uploading.

GoGoHam then writes one text file per band, e.g. DL1ABC_A_2m.txt (call, section, band): the cover sheet following form 01/2026 at the top (the part for the log checker stays empty), below it the log sheet with time (UTC), call, RST+no. sent and received, locator, km and remark, 50 QSOs per sheet with a subtotal. Total km, number of QSOs, km/QSO, best DX and countries worked are calculated by GoGoHam; duplicate QSOs are listed with 0 km and “Dupe”. The file uses the Windows character set, like the organiser's own software. Then “Where does the log go?” opens the e-mail to logs@bergtag.de together with the folder to drag the files from. No extra program needed. The sheet itself is in German – it goes to the German log checker.

To be honest (BBT): The rules do not require a handwritten signature; GoGoHam writes the confirmation line with date and call. Only the date list on bergtag.de gives a deadline (so far the Sunday two weeks after the contest) – so GoGoHam does not calculate one. Power not from the mains and the 20 % rule for stations outside southern Germany are not checked; the yearly ranking (factor per band, winter × 1.5) is done by the log checker.

WAE and QTC

What is a QTC? In the WAE DX Contest, stations outside Europe pass their earlier contacts on to European stations – like relaying messages. A QTC is one line with time, callsign and serial number, e.g. “1307 DL1ABC 042”: W1AW worked DL1ABC at 13:07 UTC and received number 042. Every QTC counts 1 point for both sides – as much as a QSO. The other station first announces the series, e.g. “QTC 3/5” = its 3rd series with 5 QTCs. At most 10 QTCs are allowed between two stations (all bands together).

How it works in GoGoHam (your station in Europe):

  1. Log the QSO with the DX station. The message line at the bottom then shows e.g. “QTC possible from W1AW: 10 of 10 left (Ctrl+Q)”; the info box shows it too while you type the callsign.
  2. Ctrl+Q opens the QTC window. The callsign is already filled in (callsign field or last QSO).
  3. Type the announced series, e.g. 3/5, then Enter.
  4. One line per QTC: 1307 DL1ABC 042 + Enter. Each line gets a ✔ or the reason why it does not fit.
  5. Enter on an empty line (or Done) saves the series. The points show up in the score at once (row “QTC”).

What GoGoHam checks: at most 10 QTCs per station (there are only as many lines as are still allowed) · your own callsign must not appear · the same contact not twice · the time must exist (e.g. not 2575) · an incomplete callsign like DL1A? is not accepted – please ask again. If the number of lines does not match the announced series, GoGoHam asks. If there is no QSO with the station in the log yet, you get a hint.

Changing later: Log & Contest → QTC → QTC list … shows all QTCs (received and sent); series, time, callsign and number can be changed by double-click, selected rows deleted.

In the log: the Cabrillo export writes the QTCs as separate QTC: lines as required by DARC (frequency, mode, date, time, your callsign, series, callsign of the DX station, then the reported QSO). The ADIF for your logging program contains only the QSOs. GoGoHam fills in time, band and frequency of the QTC reception itself.

Multipliers and score: in the score table the band factor is shown right at the band (“80 ×4”). In the “Total” row the multipliers are already added up with their factor; the score is (QSOs + QTCs) × this total. For W, VE, VK, ZL, ZS, JA, BY, PY and RA8/9/0 the call area counts instead of the country – the digit in the callsign decides, also after a slash: K3ABC/1 counts as W1, VO1AA as VE1, 7K4AA as JA4.

Only Europe ↔ outside Europe: QSOs between two European stations do not count in WAE; GoGoHam shows this while you type. Nothing is transmitted when receiving QTCs – the window is only for writing down.

WAE RTTY (from 0.10.7): here every station may send and receive QTCs – but only with stations on another continent, and at most 10 QTCs in total between two stations (sent + received). Ctrl+Q therefore first asks “Receive or send?”. When sending, the lines go out through fldigi – as in CW only when you press Enter or F2.

Sending QTCs (station outside Europe)

If your station is outside Europe, you pass QTCs on to European stations. The rules: each QSO may be reported only once as a QTC and never to the station you worked in it. A station gets at most 10 QTCs from you (also spread over several contacts). You number your series consecutively: “QTC 3/7” is your 3rd series with 7 QTCs. Each confirmed QTC gives you 1 point.

  1. Log the QSO with the European station. The hint line then shows e.g. “QTC possible to DL1ABC: 10 of 10 left (Ctrl+Q)”.
  2. Ctrl+Q opens the Send QTC window. The callsign is already filled in. GoGoHam has already picked the QSOs – the oldest ones not reported yet, without QSOs with the receiver itself, without dupes and without QSOs lacking a number (“000”). Use the tick in the Include column to leave out or add single ones; the series is shown at the top, e.g. “QTC 4/10”.
  3. In CW: Enter sends the series (“QTC 4/10”), every further Enter sends the next line, e.g. “1307 DL1ABC 431” – and the previous one counts as confirmed. F2 sends the same again if the other station asks. Sending goes via the WinKey or the radio, only when you press the key.
  4. In SSB: GoGoHam transmits nothing. The line that is due is shown in large letters – you read it out. Enter = next line (the previous one counts as confirmed). If you like, the line can also be announced (Settings → Sound & announcements → Announcements → “Sending QTCs in SSB”, only via the sound card, never to the radio) – meant above all for blind radio amateurs.
  5. After the last line, Enter saves the series. Done or Esc also work earlier: GoGoHam asks whether the last line was confirmed or whether the confirmed QTCs should be saved. Only confirmed QTCs count; the series keeps the announced number.

In the Confirmed column you can also set or remove a tick by hand. In the Cabrillo log, sent QTCs appear with the European station as receiver and you as sender.

Not possible yet: sending QTCs in practice mode.

Entering the exchange: in WAG, Christmas, Easter and the two training contests you type the DOK for German stations (B36, special DOK or NM) and the serial number for all others. In the 10 m contest DL stations send serial number and DOK – both go into the one field, separated by a space: 12 B36. GoGoHam fills in your own DOK and serial number itself.

Frequency segments: if you operate in a contest-free segment (WAG, WAE DX, training contest, e.g. 40 m CW 7040–7200 kHz) or outside the permitted segments (10 m, Christmas, Easter), a hint appears. The QSO still counts – penalties are up to the organiser.

The Cabrillo log names the contest “WAG”: the DARC gives no name of its own, recommends the WAG setting for programs without this contest and recalculates the score itself. DO stations may not operate on 40 m under their licence.

CW training contest (CWA): meant for practice – the speed should be between 12 and 22 WPM.

What to ask for? As long as the exchange field is empty, the info box shows what the other station will send – e.g. “State: ask” (USA), “Number: ask” (DX in ARRL 10 m), “ITU region: ask” (maritime mobile) or “Year of first licence: ask” (EU HF).

Society stations in IARU HF: call signs ending in “HQ” (DA0HQ, OL9HQ, TM0HQ …) get no prefilled zone; the info box says “Society station? Ask for the abbreviation (e.g. DARC)”. Society stations without “HQ” in the call sign (e.g. W1AW) are not recognised by GoGoHam – just type in the abbreviation there.

Only the frequency is changed – nothing is transmitted. Without CAT only the band selection is changed; while an FT8 program is in control, GoGoHam does not ask.

Band/mode changes (EU HF): GoGoHam counts the changes in the current clock hour (band and mode at the same time = one change; a change at the turn of the hour counts for the new hour). At the 10th change a hint appears, from the 11th a warning; the log check lists all hours with more than 10 changes. GoGoHam only counts – any points are deducted by the organiser.

The Canadian province is prefilled from the call sign if it is unambiguous (e.g. VE3 = ON). The abbreviations follow the official ARRL list; common other spellings (e.g. VO1, PEI, VE3) are understood. QSOs that do not count according to the rules (e.g. DL–DL in ARRL DX) are logged but score 0 points and are marked in the log check. 22. Rule files

Every contest has its own small text file (JSON format) containing its rules: bands, mode, exchange, points, multipliers, schedule, log format and the columns of the log table. GoGoHam reads these files at start-up. The calculations – such as how a call sign becomes a WPX prefix or how the distance between two locators is computed – remain in the program. The file only says which building blocks a contest uses and with which numbers.

The names in the files are English so that radio amateurs from all countries can contribute rules. The table below explains everything.

Where are the files?

~/.local/share/gogoham/rules/Your own rules (optional – only if you create something yourself). They always take precedence. A file here replaces the official one with the same id and is never overwritten by updates.

New rules from GitHub

The official collection is at github.com/do2ggh/GoGoHam-rules (licence CC BY 4.0). GoGoHam checks there

  • automatically when creating a new log (can be switched off),
  • during the daily update at startup (not while the contest of the open log is running), and
  • any time via File → Settings → Data & updates → Update contest rules now.

Only new or changed files are downloaded; each one is checked (checksum, rules check, matching GoGoHam version) before it is used. Without internet nothing happens – the existing rules apply. No data about you is sent.

Rules watch: every Monday GitHub automatically compares all official contest rules with the version the rule files were last checked against. If an organiser changes the rules, this is noticed quickly and the rule file is updated – you then receive it automatically as described above. Your GoGoHam itself never contacts the organisers' websites for this.

The log remembers its rules

When a log is created, GoGoHam stores the rules in the log itself. If the rules change later, points and score of an existing log stay exactly the same. Logs from older versions remember the rules that apply at the time they are first opened.

If there are other (newer) rules for the contest, Log & Contest → Log settings says so and shows the button “Apply newer rules”. Only after clicking it and OK do they apply to this log; the points are then recalculated. It also says where the log's rules come from (“stored in the log”, “from GitHub”, “built in” or “own rule file”).

To change a rule, e.g. because the official rules have changed: copy the built-in file to the folder ~/.local/share/gogoham/rules/, edit it there and restart GoGoHam.
mkdir -p ~/.local/share/gogoham/rules
cp ~/.local/share/gogoham/app/gogoham/rules/cqww-ssb.json ~/.local/share/gogoham/rules/
If one of your own files is faulty (typo, missing comma …), GoGoHam reports what is wrong at start-up – with line and column – and uses the built-in rule for this contest. So nothing breaks. To reset, simply delete your own file.

23. DX cluster and band map

A DX cluster is an internet service where radio amateurs worldwide report whom they hear where (“spots”). GoGoHam reads these reports and shows them in the band map – a list to the right of the log (below Super Check Partial). GoGoHam only reads; it never sends spots of its own.

Switching it on

Window → Band map – opening the band map connects GoGoHam to the DX cluster, closing it disconnects – unless the map is showing cluster spots (see Extra windows). Node, call and filters are set under File → Settings → Online services → DX cluster. The default is the German node DB0SUE; other tested nodes (HamQTH, DXSpider UK, DX Fun, W3LPL, VE7CC) are available, or your own as “address:port”. You log in with your call from the log – no password is needed. Without internet the status bar shows e.g. “Cluster: Node not found – no internet connection?”; GoGoHam then retries by itself. If the internet drops during operation (e.g. cable unplugged), GoGoHam notices after about a minute without data at the latest and reports “Connection lost – no answer from the node”.

Filter by region

  • Spotted by: which region the reporter is in. The default is your own continent – so you only see stations that can be heard where you are.
  • Spotted station from: which region the reported station is in (default: all).
  • Only spots on the contest’s bands and mode (on by default): in an SSB contest no CW or FT8 spots.
  • Spots disappear after 30 minutes (adjustable).

The band map

Open and close it via Window → Band map (open = connected to the cluster). It always shows the band you are on (named in its title, e.g. “Band map 40 m”), sorted by frequency. Your own frequency is shown in blue in between (“◀ you are here”). The number in the status bar (“18 spots (all contest bands)”), on the other hand, counts all spots that pass your filters – on all bands of the contest.

Right click on a spot: “Look up … on QRZ.com” opens the station’s QRZ.com page in your browser. The radio is not retuned.

Wide band map: If the window is wide enough, the list runs in newspaper columns – the frequencies go down the first column and then continue at the top of the next column. That way the order by frequency is kept. If it is narrow, it stays one column as usual.

  • Green with ★ = new multiplier on this band – worth the most.
  • Orange with ↕ = still a needed multiplier on another band. Here the station gives no new multiplier (or you have worked it already), but a band change is worth it. Hover over it to see on which bands the multiplier is still missing. (Only in contests that count multipliers per band.)
  • Normal = new QSO with points.
  • Grey struck through = already worked (dupe).
  • Grey italic = does not count in this contest.
  • Older spots get paler; the number with ′ is the age in minutes. Hover over a spot to see who reported it and when.

Clicking a station sets the radio to its frequency and mode (CW, below 10 MHz LSB, above USB), enters the call in the entry field and switches to S&P. Nothing is transmitted. The radio chooses the filter itself – on every mode change GoGoHam uses the default filter the radio provides for that mode. While an FT8 program is active, GoGoHam does not change the frequency.

ASSISTED category: using a cluster in a contest usually means entering the ASSISTED category. If your log is set to NON-ASSISTED, GoGoHam shows this in orange in the status bar. Change it under Log & Contest → Log settings → Assisted.

24. Beacon display (NCDXF/IARU)

The 18 beacons of the international beacon project (NCDXF/IARU) are spread around the world and take turns transmitting for 10 seconds each on 14.100 / 21.150 / 28.200 MHz (and on the WARC bands) – one cycle takes 3 minutes. If you hear one, you know: the band is open in that direction right now. GoGoHam shows this without you having to retune the radio.

How it works

The Reverse Beacon Network (RBN) is a network of receivers (“skimmers”) all over the world that listen and report what they hear – including the beacons. GoGoHam logs in there with your call sign (read only, nothing is transmitted) and only uses reports from receivers within 1000 km of your location: what they hear will very likely reach you as well. GoGoHam takes your location from the locator in the log settings, otherwise from your country. The radio is not touched at all.

Important – the 1000 km apply to the receivers, not to the beacons. The beacons are deliberately spread around the world (New York, Hawaii, New Zealand, Japan, South Africa …); each one stands for a direction. Example: if 4U1UN (New York) shows green “23 dB” on 20 m, a receiver e.g. in Thuringia has heard the beacon in New York well – so the band is open from here towards North America (297°) right now, even though the beacon is 6000 km away. Why 1000 km: receivers up to that distance show almost the same picture as the very close ones (up to 500 km), but there are enough of them in case some are switched off. Further out (Scotland, Ireland, the Baltics, Sicily) propagation is often different already.

Switching it on

Window → Beacons (NCDXF/IARU). This only works for contests with 20, 15 or 10 m – exactly these beacon bands of the contest are shown (17 and 12 m are WARC bands without contests and are therefore left out). Without internet the display cannot be switched on; the message line at the bottom then says “no internet connection” in red. As with all extra windows: window open = on, window closed = off – whether via the menu, the right-click menu or the X (unless the map shows beacons; then the connection stays for the map). If you switch to a log without these bands, the window closes. At program start it is only open if you have ticked it under File → Settings → Display → Open at program start (see Extra windows).

What the colours mean

  •  Green  – heard well in the last 15 minutes (10 dB and up). The number is the strongest value.
  •  Yellow  – only heard weakly, or last heard 15 to 30 minutes ago.
  • – (grey) – not heard by any receiver near you for 30 minutes.

The Direction column shows the compass bearing of the beacon from your location (0° = north, 90° = east). Move the mouse over a cell to see which receivers heard the beacon, how far away they are from you, when and how strong.

Patience after switching on: The RBN does not deliver any history, and each receiver reports the same beacon at most about every 10 minutes. The table therefore fills up gradually – after 10 to 15 minutes the picture is complete. At night and with closed bands it stays mostly grey; that is then the correct answer.

Category: Some contest rules count any use of the Reverse Beacon Network as assistance (“Assisted”). If your log is set to NON-ASSISTED, GoGoHam therefore warns you as with the DX cluster: in orange in the beacon window and once in the message line at the bottom. When in doubt, leave the beacon display switched off and check the rules of the contest.

25. Band opening forecast

Window → Band openings (forecast) shows an estimate of which HF band is open from your location to where right now – and how it looks over the next 12 hours. The window does its own calculation, without any internet service and without extra programs. The radio is not touched.

Two views

  • Now: bands × continents – rows are the HF bands of the contest, columns the continents EU, NA, SA, AF, AS and OC.
  • Next 12 hours – for a continent you pick next to it: a column "now" and then one per hour (times in UTC, each calculated for half past).

GoGoHam remembers your choice. The display is refreshed continuously.

What the cells mean

  •  ●●●  good ·  ●●  fair ·  ●  weak · – closed
  • ✓ = actually heard in the last 30 minutes: if the DX cluster is running (band map open, or map with spots), spots of stations on that continent count when the spotter is within 1000 km of you – what they hear very likely reaches you too. Contacts under 300 km do not count (that is ground wave). If the beacon display is running, beacons heard by receivers near you count too. The window itself connects to nothing – without cluster and RBN there is no ✓.

Move the mouse over a cell to see where it works best (e.g. "US/Canada east coast" or "Canaries/Morocco"), the estimated highest and lowest usable frequency, the path length and the number of hops – and whether the path crosses the auroral zone.

How it is estimated – and its limits

GoGoHam takes the solar flux (SFI) and the K index from the space weather in the bottom bar and calculates each path with simple rules of thumb:

  • How high the bands go: the higher the SFI and the more daylight at the reflection points of the path, the higher the bands (10, 12, 15 m). In winter the layer is denser at noon, in summer the nights are better. After sunset the layer decays only slowly (over about 3 hours) – that is why the high bands stay open for a while in the evening.
  • How much the low bands are absorbed: daylight on the path weakens 160, 80 and 40 m – the more daylight and the more hops, the stronger. At night they are open.
  • Disturbed magnetic field: a high K index downgrades paths across the far north (e.g. from Europe to North America or Japan), and a very high K all paths.

To be honest: this is a rough estimate, rougher than big prediction programs. For each continent GoGoHam calculates several areas with a lot of radio activity (e.g. North America: east coast, Midwest, west coast, Caribbean) and shows the best one – "open" means "to somewhere on this continent". Only the short path is calculated; long path, sporadic E, auroral propagation and your antenna and power are not known to it. It does not calculate paths shorter than 800 km. Only listening shows whether a band is really open – that is what the ✓ is for. There is no forecast for VHF/UHF (6 m and up); in VHF contests the window says so. Without current space weather (no internet) GoGoHam assumes medium solar activity and shows "without current space weather, day/night only" at the top.

Like all extra windows: window open = on, closed = off; open at program start only if ticked under File → Settings → Display → Open at program start (see extra windows). The calculation needs your location: the locator from the log settings, otherwise the middle of your country.

  • Relief (Natural Earth) – an atlas map with hill shading and colours for mountains, forest and desert; the night side is darkened. About 90 MB download (about 12 MB stay on disk).
  • Simple (no download) – land and sea in calm colours, always included.

When you choose a background for the first time, GoGoHam asks whether to download the images. While loading, the map shows the progress at the top left and the simple map meanwhile. If you say “No”, the simple map stays. You can also do it by hand under File → Settings → Data & updates. The daily update fetches the NASA image of a new month by itself. When you zoom in, GoGoHam loads more detailed parts of the image (down to about 2 km per pixel for NASA, 4 km for the relief) – very close the image gets soft; grid, borders, cities and paths stay sharp.

Two kinds of map

  • World map – the familiar rectangular map. Good for seeing day/night and the twilight zone all around the earth.
  • Azimuthal map – your own location (locator from the log) is the centre. Every straight line from the centre outwards is a beam heading; the degree ring at the edge shows it (0° = north, 90° = east). The dotted rings stand for 5,000, 10,000 and 15,000 km, the outer edge is your antipode (about 20,000 km). Far-away countries look distorted – that is how this kind of map works and intended: heading and distance are correct.

Switch in the selection box at the top left of the map window.

What is shown – each item can be switched on and off

  • Day/night – the night side is dark, the yellow sun marks where it is right overhead. The map follows the time (redrawn every 30 seconds).
  • Twilight (grey line) – a soft transition while the sun is up to 12° below the horizon. DX on the low bands often works especially well in this strip. Without the tick the border is sharp.
  • Path to the other station – as soon as you type a call sign: short path solid, long path dashed, both green with a dark outline (easy to see on any background). Heading and distance are shown at the top left (e.g. “SP 296° · 6,094 km”). As in the info box, the location comes from the received locator (VHF, WW Digi), otherwise from the country file (centre of the country or area).
  • Locator grid – appears when you zoom in, as soon as the squares are easy to see: first the fields (JN), then the squares (JN59), very close the subsquares (JN59me). Coarser borders are drawn thicker; the label sits at the top left of each square, in grey with a light outline (readable on any background) – and only if it fits into the square.
  • Rivers – the big ones first, more as you zoom in. Lakes are always shown.
  • Cities – fully zoomed out only the big ones (capitals, world cities), more as you zoom in, down to towns like Ingolstadt or Coburg. Names never overlap – what has no room appears when you zoom in further. Capitals have a slightly larger dot.
  • Beacons (from 0.8.20) – the 18 NCDXF/IARU beacons as triangles at their location, in the colours of the beacon display: green = heard well, yellow = weak or 15–30 minutes ago, grey = not heard. Shown for the band you are on; on bands without beacons (e.g. 40 m) the best of 20, 15 and 10 m – the top left corner of the map says which. The map connects to the Reverse Beacon Network by itself – the beacon display window does not need to be open (from 0.8.20.1). After switching on it fills up within 10–15 minutes. Only for contests with 20, 15 or 10 m.
  • Cluster spots (from 0.8.20) – the spots on the band you are on as dots at the location of their country (from the country file, so not exactly where the station is). Colours as in the band map: green = new multiplier, orange = multiplier on another band, white = new QSO, grey = already worked. Several spots from the same country share one dot (“JA1ABC +2”). Mouse over it: all calls with frequency. Click = as in the band map (tune the radio, enter the call – nothing is transmitted); with several spots you pick from a small menu. Right click = look up the call on QRZ.com. The map connects to the DX cluster by itself – the band map does not need to be open (from 0.8.20.1).

Connections: the cluster and the Reverse Beacon Network run as long as anything needs them – band map or beacon display open, or the map open with the matching tick. Close the map or remove the tick (with the other window closed) and they disconnect. As always: some contests count cluster and RBN as assistance (ASSISTED).

In practice mode (from 0.10.19) the map shows the simulated spots of the practice session for S&P and mixed – the same as in the band map – not real cluster spots. Run practice has no spots; the map says so at the top left. The beacons are real in practice too: the Reverse Beacon Network is only listened to, nothing is transmitted.

The two rows above the map hold these ticks and the kind of map.

Mouse: heading, distance, zoom

  • Mouse wheel – zooms in and out where the mouse is (up to about 600 times).
  • Drag with the left mouse button held – moves the enlarged map.
  • Double click in the map – back to the whole map.

28. Announcements (speech output)

GoGoHam can read important things aloud. This is meant above all for visually impaired radio amateurs, but it also helps if you do not want to look at the screen during a contest. Switch it on under File → Settings → Sound & announcements → Announcements (default: off). GoGoHam remembers the setting: once you have switched the announcements on, they are on again at the next start.

Where the sound goes: The announcements use the normal speech output of the system, i.e. the speakers or headphones set as default in the system. GoGoHam never keys the PTT for this. If the sound card of your radio is the system default, set the PC speakers or the headphones as default in the system.

Natural voice (Piper, from 0.8.26.2): Piper sounds best. Its voices sound almost human and work without internet. In the Announcements tab (and under Data & updates) the button Download natural voice (Piper) loads the Piper program and one voice each for German (“Thorsten”) and English (“Cori”), about 150 MB together. No password is needed. Everything goes only into GoGoHam’s own folder (~/.local/share/gogoham/piper), and every file is checked with a checksum. Afterwards the announcements use the new voice at once. With Piper an announcement takes a short moment longer because the voice is computed first. Voice “Thorsten” from the Thorsten-Voice project (CC0), voice “Cori” from LibriVox recordings (public domain). Both are free to use.

Speech output: With “Automatic” GoGoHam first uses Piper if it is loaded, otherwise speech-dispatcher if it is installed. This is the speech output that screen readers such as Orca use, with the voice you have chosen there. Otherwise GoGoHam uses espeak-ng. If none of them is there, the tab tells you what is missing.

Installing speech-dispatcher with one click (from 0.8.26.1): If speech-dispatcher is missing, the Announcements tab has the button Install speech-dispatcher now; the same button is also under Data & updates. Afterwards the announcements use speech-dispatcher at once, without a restart. If it does not work (e.g. on another distribution), GoGoHam shows the commands to copy.

Test plays an example sentence. You can also set the speed and whether calls are read as single letters (D O 2 G G H) or with the phonetic alphabet (Delta Oscar 2 Golf Golf Hotel).

29. Practice mode

File → Practice mode … lets you practise a contest without transmitting: made-up stations call you through the sound card, and you work them exactly as in a real contest – with F1–F8, with Enter (ESM), Super Check Partial and live dupe checking. At the end GoGoHam shows what went well and where the errors were. Practice mode is available for CW and SSB (see below).

Nothing is ever transmitted. During practice the radio (including PTT and keyer), WS, DX cluster and live score are disconnected. So that you don't mistake practice for the real thing (and reach for the microphone), it is clearly marked (from 0.10.19): a bright yellow border around the whole window, "⚠ PRACTICE MODE – nothing is transmitted" at the front of the window title (also in the taskbar), a yellow bar at the top saying "PRACTICE – nothing is transmitted" in large letters and a yellow callsign field. After practice everything is back to normal. You hear your own CW only as sidetone and your voice recordings only through the PC's sound card. Choose the PC's headphones or speakers for playback – not the radio's sound card: with VOX switched on it could otherwise transmit. GoGoHam warns if the choice looks like that.

Settings

  • Practice – Run (you call CQ), S&P (you search with the VFO knob, see Practising S&P) or Mixed (both, see Mixed practice). S&P and Mixed need a configured radio.
  • Mode, contest and band – CW or SSB; all HF contests in that mode for which GoGoHam can create the other stations' exchange are offered (VHF and digital not yet). With S&P and Mixed the band comes from the radio.
  • Duration – 10, 30 or 60 minutes, or no end.
  • Speed of the stations (from–to) and your speed with the pitch of your sidetone.
  • Activity – from "quiet" (a caller now and then) to "pile-up" (often several at once).
  • Noise, fading (QSB), QRM (other stations next to you), double calls and cut numbers (T = 0, N = 9). In SSB the noise is quieter than in CW at every level, and the voices are a little louder (from 0.8.30). This keeps the computer voices readable.

GoGoHam remembers the settings. Call sign, locator and your details (e.g. DOK) are taken from the log that is currently open.

How a practice session works

  • Call CQ with F1 (or Enter). Then one or more stations call you – each with its own pitch, speed and loudness.
  • If you send a call sign back correctly (F2 or Enter), that station sends its exchange. If you send a wrong one, it repeats its call sign. With part of a call sign and a question mark (e.g. "ABC?" via F5 or your own macro) only the matching stations answer. AGN?, ? or NR? make the station repeat the exchange.
  • With TU (F3, or Enter after logging) the QSO is complete – then the next ones call. Stations that get no answer for too long give up.
  • Esc stops your sending.

The call signs come from the Super Check Partial list (real active contest stations). Which continents call more often follows the band opening forecast for band and time – so in the evening on 80 m you get other stations than at noon on 15 m. Only stations that may work you under the rules call (in ARRL DX from Europe, e.g., only USA and Canada). GoGoHam creates the exchange to match the contest: the CQ zone from the country file, serial numbers, DOKs from the call history or the DOK list, and so on.

Practising SSB

Choose Mode: SSB at the top. The other stations speak English with the phonetic alphabet ("Delta Lima one Alpha Bravo Charlie … five nine, fourteen"), each with its own voice, speaking speed and loudness, with noise and fading as over the air (300–2700 Hz only).

  • Voices: it sounds most natural with Piper and the voice "libritts_r" (904 different speakers). Button Load natural voices in the practice window – about 79 MB once (about 105 MB including Piper itself if it is not yet loaded for the announcements), then without internet. Without this download GoGoHam uses espeak-ng if it is installed (computer voice). Origin: LibriTTS-R data set (CC BY 4.0, openslr.org/141), voice from rhasspy/piper-voices.
  • Your side: if you have your own voice recordings (see function keys and voice memories), GoGoHam plays them with F1–F8 or Enter – only through the PC's sound card. Otherwise you speak yourself (nothing is transmitted) and press the key; the top line then says "Speak now: …". GoGoHam knows from the key what you said: F1 = CQ, F2 = call sign and exchange, F3 = TU, F6/F7/F8 = repeat – just as you set up the SSB keys. For a partial call ("ABC?") type the part with a question mark into the call field and press F5.

Practising S&P (with the VFO knob)

With Practice: S&P it is the other way round: on a piece of the band invented stations call CQ, each on its own frequency. You turn the VFO knob of your radio, find them and call them – in CW and in SSB.

  • Only with a configured radio. GoGoHam connects for listening only: it reads frequency and mode. Transmitting is blocked – no PTT, no CW, no voice memories, no WinKey, no PTT line. Clicking a spot in the band map only sets the frequency.
  • The band comes from the radio. If you switch the radio to another band, a new piece of band fills up there (e.g. CW 14,000–14,060 kHz, SSB 14,150–14,340 kHz). A band that is not part of the contest stays silent; the yellow bar tells you.
  • You hear the sound through the PC sound card, not from the radio – so turn the radio speaker down. Tuned exactly, a CW station sounds at your pitch; next to it higher or lower, outside the filter (about 500 Hz wide) not at all. In SSB a station is only readable when tuned exactly, next to it the voice sounds distorted.
  • Calling: enter the station's call, send your own call (F4, or Enter with "Enter sends" – GoGoHam switches to S&P for this). The station only hears you if you are close enough to its frequency (CW about 200 Hz, SSB about 700 Hz) and not while it is transmitting itself.
  • It gives you the exchange. Sometimes it got your call wrong ("DO2GCH 5NN 14") or only partly ("DO2?") – then send your call again, best together with the exchange. Your exchange → "TU", the QSO is in its log.
  • Sometimes someone else calls at the same time (weaker, slightly off frequency) – then it works that station first. Stations come and go; stations already worked stay on the band.
  • Spots in the band map (tick box, on by default): some of the stations are reported as if by a DX cluster – sometimes a little off frequency, rarely with a wrong call. The rest you only find by tuning. After the session these spots disappear again.
  • To be honest: how smoothly the tone changes while tuning depends on how fast your radio reports its frequency. GoGoHam measures this and asks as often as possible (IC-7300: 50 times per second; see Radio → Advanced settings → Frequency polling). With slow radios the tone moves in small steps.
  • How many stations call is set with Activity: in CW on 20 m from 15 (quiet) to 100 (pile-up), in SSB from 10 to 55, on narrower bands correspondingly fewer. In SSB GoGoHam computes the voices first for the stations near your VFO frequency; with many stations the computer is busy for a while at the start – a station whose voice is not ready yet calls a little later.

Mixed practice: Run and S&P (from 0.8.30)

With Practice: Mixed you do both, as in a real contest: you call CQ on your own frequency, and in between you tune away and search for stations. As with S&P this needs a configured radio, which GoGoHam only listens to. Nothing is transmitted.

  • Your run frequency is where you call CQ (F1 or Enter). If you call CQ somewhere else, it moves with you, also to another band. The yellow bar shows it.
  • On the run frequency (CW ± 150 Hz, SSB ± 400 Hz) stations call you as in Practice: Run. They sit there on the band: if you tune away, you no longer hear them. Anyone who was about to call you will not wait long.
  • Away from the run frequency everything works as in S&P. The S&P stations keep your run frequency clear.
  • "Enter sends" switches by itself: on the run frequency it is set to Run, when you tune away to S&P. You can still switch yourself with Ctrl+Tab. That stays in effect until you next tune onto or away from the run frequency.
  • Frequency gets taken (tick box, off by default): if you are away for more than 1-2 minutes, another station calls CQ on your run frequency. While it is there, hardly anyone calls you. Then find a new frequency with a CQ.
  • Results: also split into Run and S&P, i.e. QSOs, minutes, rate and errors. Run minutes are the time your VFO was on the run frequency.

Results

When the time is up, or with End practice (button in the yellow bar or File → End practice), GoGoHam shows: number of QSOs, how many were without errors, the rate per hour and a list of errors – wrong call sign ("DL1ABD logged – correct was DL1ABC"), wrong exchange, QSOs without a counterpart, and stations that sent their exchange but were not logged. With S&P also: stations that logged you wrongly (you should have corrected them) and unnecessary dupes. Below are your last practice sessions in the same contest for comparison. Afterwards GoGoHam opens your previous log again and connects the radio as before.

Practice logs are kept separately in ~/GoGoHam/Übung/ and never mix with real logs; you can delete them at any time. On the next program start GoGoHam opens your real log again.

To be honest: the stations follow simple rules – real operators are more varied. How it sounds depends on sound card and headphones; try different noise and volume settings.

30. Station log – several positions in the network (multi-op)

At a multi-op station several operators work several radios – each position has its own computer with GoGoHam, but all of them write one common log. All computers must be at the same location in the same network (cable or Wi-Fi in the club house or on the field day site). Over the internet this deliberately does not work.

Creating a station log (on the first computer, the main position): fill in Log & Contest → New contest log … as always, with the station callsign (e.g. DL0ABC) as your callsign, then tick “Station log for several positions” and make up a station password (at least 4 characters). That is all.

Joining (on all other computers): start GoGoHam – nothing else. As soon as GoGoHam notices a station log in the network, it asks: “The station log DL0ABC – … is running in the network. Join?” With Yes and the station password you are in: GoGoHam creates its own log file in the folder ~/GoGoHam (station-…ggh) and fetches the complete log. GoGoHam remembers the password; at the next start “Continue” is enough and it reconnects by itself. If you do not want to join, click No – GoGoHam will then not ask again for this station log.

Who is operating? The first time, GoGoHam asks for the operator's callsign. It is stored with every QSO and listed in the Cabrillo log under OPERATORS. At a change of shift: Station → Change operator …. The name of the position is the computer's name; it can be changed under Station → Station log ….

How the station log works:

  • Every QSO, every change and every deletion goes to all positions at once. Dupes, multipliers and points apply to the whole station – so while typing you see whether another position has already worked the station.
  • Serial numbers are handed out by the main position. Each position gets its next number reserved; therefore numbers may not be in exact time order in the log – that is fine.
  • The state is shown at the bottom right, e.g. “Station log: connected · 3 positions · OP DO2GGH”. Red means “no connection to the main position”: just keep logging, the QSOs wait and are sent as soon as the connection is back. Without a connection, however, GoGoHam cannot know which number is free – then please watch out for duplicate numbers.
  • The main position must run as long as the contest runs. If it is restarted briefly, all positions reconnect by themselves.

Station → Station log … shows all positions (with operator, band and mode), the station logs in the network and – on the main position – its address.

“Station” window: all positions at a glance, messages

Open the window via Window → Station (positions and messages), with a mouse click on the station log display at the bottom right of the status bar, or with Ctrl+T (the cursor then goes straight to the message line; also via Station → Message to other positions …). Like all extra windows it can be docked; it only opens at program start if you tick it under Settings → Display.

At the top there is one line per position: position, operator, transmitter (e.g. run/multi), band, frequency, mode, number of QSOs and the rate (QSOs per hour, counted over the last 10 and 60 minutes). Your own position is bold. A band change shows up for everyone at once, the frequency after 5 seconds at the latest. Positions that were disconnected stay in grey (“disconnected since 14:05 UTC”); positions that only appear in the log are shown as “not connected”.

Same band: If two or more positions are on the same band, their lines turn red. If another position is on your band, the hint line warns once, e.g. “Caution: position “Laptop” is also on 20 m”. The warning also comes when the window is closed – it is part of the station log. If you like, you can also have it announced (Announcements → “another position is on the same band”, off by default).

Messages: At the bottom choose To: “all positions” or one position, type the text and press Enter or click Send. Messages only go over the network (encrypted like the log), never over the radio. Behind your message it says “delivered” or “not delivered” – if the recipient is not connected right now, it does not arrive and is not sent later either. A new message appears in the hint line at the bottom (“Message from Laptop: …”); to have it read out, use Announcements → “read out messages from other positions” (off by default). Messages stay stored in the log file on this computer, but never go into Cabrillo, ADIF or other exports.

Network for club house and field day

You do not have to set up anything on the network – it is enough that all computers are connected. Three ways, all work by themselves:

  • Router (at home, in the club house): all computers via cable or Wi-Fi to the same router.
  • Switch without router (small club house, field day): all computers via cable to a network switch. No internet needed.
  • Direct cable: connect two computers with one network cable.

Without a router the computers find each other via their link-local addresses. So that the network manager does not switch off the cable port after a few minutes without a router (it would otherwise wait in vain for a router), GoGoHam asks once with the first station log: “Should this computer also work in the station log without a router?” – Yes is enough. With a router nothing changes. If a computer still ends up on a cable without an address, GoGoHam notices by itself and offers to set it up with one click. Without a router the network icon in the task bar then keeps showing “connecting …” – that is intended, the connection to the other positions works anyway. Booting without a router may take up to about one minute longer.

Station → Station log … shows under Network in plain words how the computer is connected, e.g. “Cable (enp5s0): without router – direct connection works anyway”, and whether the cable port is prepared (otherwise button “Prepare cable without router”).

Time without internet

All positions should have the same time. Without internet the computer clocks do not set themselves – so set the clock of the main position before the contest while you still have internet. The other positions keep comparing their clock with the main position. If a clock is more than 2 seconds off, a warning appears there at the bottom, and Station → Station log … offers the button “Set clock from the main position” (asks for the system password).

If the positions do not find each other:

  • Firewall: if a firewall runs on a computer, Station → Station log … shows the button “Open firewall” – one click and the system password are enough. Opened are the ports 47374 (UDP, finding) and 47375–47385 (TCP, connection).
  • Wi-Fi: some Wi-Fi networks (guest Wi-Fi, “isolate devices”) do not allow the computers to see each other. Then choose another setting on the router or use cables – or the fallback: Station → Station log … → Connect by address … and type the address shown in the same window on the main position (e.g. 192.168.178.20).

Security: without the station password no computer gets into the station log. The password itself never goes over the network, and everything transmitted is encrypted and protected against tampering. The encryption is built from Python's own building blocks – good enough for club house and field day, but not banking standard.

Practice mode always runs on your own computer only.

31. Live stick (GoGoHam from a USB stick)

GoGoHam can run from a live stick: plug in the stick, start the computer from it (when switching on, usually press F12, F8 or Esc to open the boot menu and choose the stick) – done. Nothing is installed or changed on the computer; without the stick it starts as before. The stick also starts with Secure Boot switched on (tested); if a computer still refuses it, switch Secure Boot off in the BIOS.

Everything you change stays on the stick: logs, settings and programs you install via Companion programs. Plug the stick into another computer later and everything is there again. Programs you install there (WS, fldigi) get a desktop shortcut on the stick right away (from 0.10.19) – next to "GoGoHam" and "Exchange folder". Uninstalling removes it again.

When GoGoHam runs from the stick, the settings have a section USB stick (at the very bottom of the list). On a normally installed PC it is not shown.

  • Space on the stick: how much is still free in the data area and in the exchange folder. When it gets tight (below 1 GB or below 5 %), GoGoHam warns in the hint bar.
  • Exchange folder: a part of the stick that Windows can read too – plug the stick into a Windows PC and it shows up there as a drive of its own. Open exchange folder shows it. This makes it easy to move Cabrillo and ADIF files to another computer: when you save Cabrillo, ADIF or EDI, GoGoHam on the stick suggests the folder “Export” in the exchange folder.
  • Also back up logs to the exchange folder (on by default): with every backup GoGoHam puts a copy of the log as ADIF and as a GoGoHam file into the folder “GoGoHam-Sicherung”. Practice logs are not copied. The GoGoHam file (.ggh) is a complete copy of the log – it even survives resetting the stick. To restore, open it in GoGoHam (Log & Contest → “Open log …”); the file “README.txt” in the folder says so too.
  • Clock: Windows computers keep their built-in clock on local time, other computers on UTC. At startup the stick checks whether Windows is installed on the computer and reads the clock accordingly. GoGoHam sets the time zone from your locator (only if the time would otherwise differ). With internet the stick also synchronises the clock by itself. Without internet GoGoHam only shows a calm hint “Time taken from the computer” – compare the UTC time at the top right with your phone once. As soon as the clock is synchronised, the hint disappears. If it is still wrong: Set clock … (also via Station → Check clock …) and enter the time in UTC. Only the clock of the running system is changed, never the computer's built-in clock.
  • Switching off: File → Quit and shut down … (from 0.10.20; before that under Settings → USB stick) quits GoGoHam properly after a question and switches the computer off. Only remove the stick once the computer is off – otherwise data may be lost. GoGoHam points this out once at the first start.
  • Reset stick to factory settings …: after a safety question, deletes all logs, settings and programs installed later. The computer restarts, and the stick is like new. The exchange folder is kept.

Updating GoGoHam on the stick (from 0.10.24)

For a new GoGoHam version you do not need a new stick: Help → Check for a new version … opens the window Update GoGoHam on the stick. One click on Look for a new version and update fetches the newest version from the GoGoHam package source (the computer needs internet for this); then Restart GoGoHam now restarts GoGoHam. Logs and settings are kept; the open log is saved and opened again.

  • It is checked like every system update: the package source must be signed correctly, otherwise GoGoHam downloads nothing.
  • The new version is stored in the data part of the stick. At start GoGoHam always takes the newer one: the installed update or the version that came with the stick. If you later write a newer stick image (keeping the data), GoGoHam removes the old update by itself.
  • If a new version needs programs that are missing on the stick, GoGoHam installs nothing and says that a new stick image is needed.
  • Back to the stick version deletes all updates; after the restart the version that came with the stick runs again. Factory reset also leads back to it.
  • New and changed rule files arrive by themselves as always – no update is needed for them.

Updating GoGoHam with one click (installed with install.sh, from 0.10.47)

If you installed GoGoHam with install.sh, Help → Check for a new version … opens the window Update GoGoHam. One click on Look for a new version and update fetches the newest version from GitHub (the computer needs internet for this); then restart with Restart GoGoHam now. Logs and settings are kept; the open log is saved and opened again.

  • Checked first: GoGoHam only downloads from GitHub, unpacks safely, checks that the announced version really is in the archive and loads it once as a test. If the new version needs something your computer lacks (e.g. a new system package), GoGoHam says so and everything stays as it is – updating never installs system packages.
  • It is put in place at the restart, before the program is loaded. The previous version is kept as a fallback: Back to the previous version in the same window switches back at the next start.
  • The start menu entry and icons are renewed as well. Running install.sh again still works and is needed if a new version requires new system packages.

Writing the stick yourself (Rufus, Etcher, dd)

The stick image can be written to a stick (16 GB or more) with any common program: balenaEtcher, Fedora Media Writer, dd – or Rufus on Windows, but there be sure to use DD mode (Rufus asks). On the first boot the stick sets itself up (from 0.10.22): it creates the data part for logs and settings and the exchange folder in the free space. This takes one to a few minutes once – the boot screen says "Stick is being set up", do not unplug. Only the stick being booted from is touched, and only its free space.

If the data part is still missing (stick under 16 GB or written in ISO mode), GoGoHam warns clearly at every start: "This stick saves nothing" – logs and settings are then lost at power-off.

Creating a new stick (from 0.10.20)

If a radio friend brings their own stick, you can turn it into a GoGoHam stick right away – without internet and without a PC: Settings → USB stick → Create a new stick …

  • Plug the new stick into a second USB port. After a second or two it appears in the list, with maker, size and content (e.g. "Intenso Rainbow Line · 14.9 GB · /dev/sdb · contains: INTENSO").
  • Only USB sticks are offered – never the computer's internal disk and never the stick GoGoHam is running from. Sticks under 16 GB are greyed out and cannot be chosen.
  • Create stick … asks once more, clearly: "Everything on this stick will be deleted". Cancel is preselected – an accidental Enter deletes nothing.
  • GoGoHam writes this stick's system to the new one, then verifies that everything arrived correctly, and creates the data part and exchange folder to fit its size. Depending on the stick this takes 5 to 15 minutes; meanwhile the window cannot be closed. At the end you see the write speed of the new stick – with a note if it is slow (see Which stick?).
  • The new stick is fresh: your logs, settings, Wi-Fi and other passwords are not copied. It has the same GoGoHam version as your stick.

Which stick?

The stick needs at least 16 GB. More important than the size is the speed: while running, the system writes many small pieces to the stick, and simple sticks are very slow at that. Recommended is a USB 3 stick in a USB 3 port (usually blue).

  • When writing the stick, the writing program measures its speed and warns if it is slow.
  • With a slow stick or in a USB 2 port GoGoHam runs too, but the first start and large installations (e.g. fldigi, 1.4 GB) take considerably longer.
  • So that simple sticks run well too, the stick writes as little as possible: no system log, no automatic updates and no file indexing in the background. GoGoHam still saves your log immediately with every QSO.

32. GPS receiver

A small USB GPS receiver gives GoGoHam your position, from it the locator, and an accurate time – even without internet. This is mainly meant for portable operation, but works on a PC just as on the live stick. No extra program is needed.

Plug it in – GoGoHam recognises the receiver

  • Simply plug the receiver in, into any socket, even while GoGoHam is running. After a few seconds GoGoHam asks: “GPS receiver found … Should GoGoHam use it?” – Use, Not now or Never for this device.
  • GoGoHam remembers the device by its fixed identity (maker, model, serial number), not by the socket. Next time it carries on without asking – even in a different socket. Unplugging and plugging back in is no problem.
  • All satellite systems (GPS, GLONASS, Galileo, BeiDou) in the usual NMEA format are understood. GoGoHam finds the speed (4800, 9600 … 115200 baud) by itself.
  • If gpsd is already running on the computer (some use it for other programs), GoGoHam takes the data from there.
Safety: GoGoHam only opens devices by itself that are clearly GPS receivers (e.g. u-blox, or “GPS/GNSS” in the device name). General USB adapters (CP210x, FTDI, CH340, Prolific) are also used in radios and interfaces – on some of them a control line keys the transmitter. GoGoHam never opens such ports by itself, and for GPS it never touches a port from a radio or rotor profile. It only reads and never sends anything to the device.

If your receiver sits behind such a general adapter, choose the port under Settings → GPS and press “Check this port”. If GPS data arrives, the port counts as a GPS receiver from then on.

Settings → GPS

  • Use a GPS receiver – on/off. Receiver: Automatic (gpsd if present, otherwise the recognised receiver), gpsd or one particular device. Speed: usually Automatic.
  • Notice when the locator does not match, position for map, rotor and beacons and compare the time can each be switched off.
  • The Now box shows live: fix (2D/3D), satellites, locator, latitude/longitude, altitude, GPS time and how far the PC clock is off.
  • Offer declined devices again undoes “Never for this device”.

The status bar shows e.g. 🛰 GPS JN59me · 9 sat – green with a fix, orange while still searching for satellites (faster at a window or outdoors), grey when the receiver is not plugged in, red on a problem. A click opens the settings.

Locator

If the GPS locator differs from the locator in the open log (and stays so for 20 seconds), GoGoHam asks: “Put locator … into the log?” It never enters anything silently. If the log already has QSOs, it adds: the locator applies to the whole log – if you have moved to another site, better start a new log. A new log gets the GPS locator right away. Map, rotor bearing and beacons use the GPS position.

Time

GoGoHam compares the GPS time with the PC clock. If it is off by more than 1 second, GoGoHam asks once whether to set the PC clock from the GPS (on a PC with the system password, on the stick without). The “Set PC clock from GPS” button is also in Settings → GPS. Log times still come from the PC clock – once it is set correctly it is right for everything, WSJT-X too. If the internet is available and the time server says “correct”, GoGoHam does not ask (the time server is more accurate).

Right after switching on, some receivers do not know the leap seconds yet. Small differences (under 30 seconds) are therefore only trusted after about 13 minutes of reception. A large difference (e.g. one hour on someone else's computer) is reported after one minute. If a very old receiver reports a nonsensical date, GoGoHam does not use its time.

Allowing USB devices

Linux does not simply let programs use USB devices such as radio cables, GPS receivers, WinKeyers or rotor controllers. GoGoHam solves this with a small access rule (70-gogoham.rules): the devices then belong to the user who is logged in at the computer – right away, without a group and without logging in again, also when plugged in later. The same rule tells the background service ModemManager to leave GPS receivers alone (otherwise it takes them for a mobile modem).

  • Installed from the package repository and live stick: the rule is already included.
  • AppImage or ./install.sh: if access is missing, GoGoHam offers “Allow now” once at start – one click and the system password. Later this is under Settings → GPS → “Allow USB devices …” or the “Set up permission …” button for the radio.
  • Where this kind of access does not exist, the old way via the group remains (uucp or dialout, then log in again once).
  • The rule is then in /etc/udev/rules.d/70-gogoham.rules and stays after uninstalling, so other radio programs keep working. To remove it: sudo rm /etc/udev/rules.d/70-gogoham.rules.

Tested is reading with simulated GPS data and a simulated gpsd. It has not been tried with a real receiver yet – feedback (model and whether it worked) helps a lot: Help → Create bug report.

33. Troubleshooting

Bug report, contact DO2GGH and clock

  • Bug report: menu Help → Create bug report … The window shows everything that matters for finding a bug: version, Linux distribution, Python/Qt/Hamlib, the ports with their USB IDs, the radio settings and the recent messages. Passwords and your QSOs are not included. “E-mail to DO2GGH …” saves the report as a file in your home folder and opens your e-mail program – please attach the file yourself. Or use “Save as file …” or “Copy”.
  • GoGoHam writes its messages to ~/.local/state/gogoham/gogoham.log (at most 1.5 MB, older parts are overwritten). Crashes are recorded there with the exact error text.
  • Contact DO2GGH (in the menu bar, only in versions before 1.0): opens an e-mail to do2ggh.de@gmail.com – for ideas, praise and questions. For bugs please use the bug report.
  • License and contributing (from 0.9): GoGoHam is licensed under the GPL-3.0 (version 3 only) with two additional terms – text in LICENSE and ADDITIONAL-TERMS.md, third-party components in THIRD-PARTY.md. Bug reports and ideas are welcome on GitHub (forms “Report a bug” and “Idea or wish”), code from others is not – details in CONTRIBUTING.md. What changed in each version: CHANGELOG.md (in German).   • Clock: at start and then every hour GoGoHam asks a time server (pool.ntp.org). If the PC clock is off by more than 2 seconds, a window appears. Synchronize switches on automatic time in Linux and sets the clock right away (Linux asks for your password once); then GoGoHam checks again. Without internet there is no warning. Check it yourself: Station → Check clock …

“CAT: disconnected”

  • Hover the mouse over the display – the tooltip gives the reason.
  • Is the radio switched on and connected via USB? ls /dev/serial/by-id/
  • “Permission denied” or “No permission”: the “Set up permission …” button or Allowing USB devices – or add your user to the group uucp (Debian/Ubuntu: dialout), then log in again.
  • Older radio via an interface: baud rate as in the radio menu? Does the interface need power via DTR/RTS? See Older radios without USB.
  • Is another program accessing the radio directly (WS, a logging program)? Switch it to “Hamlib NET rigctl” there.
  • Test in a terminal: rigctl -m 3073 -r /dev/serial/by-id/… -s 115200 f
  • Profile set to “Use an existing rigctld”, but none is running? Check the service: systemctl status rigctld

The wrong radio responds / CAT display orange

  • Are two rigctld running on the same port? Check with ss -ltnp | grep 4532. Every radio needs its own port.
  • Check the port in the profile – “Test connection” names the radio that really answers.

“UDP port in use”

Another program (e.g. a logging program or GridTracker) is already listening on port 2237. Solution: enter the multicast address 224.0.0.1 everywhere or close the other program.

Country shown as “?”

The country file is missing or old – File → Settings → Data & updates → Update country file (cty.dat).

No flags

File → Settings → Data & updates → Download flags. Missing flags are replaced by a small sign with the prefix.

Messages “qt.svg: … Could not resolve property” in the terminal

Harmless – they come from the system's icon theme, not from GoGoHam.

Log cannot be opened

See Backups and repair.

Message “Rule files” at start-up

One of your own rule files in ~/.local/share/gogoham/rules/ is faulty. The message names the place. Correct or delete the file – until then the built-in rule applies. See Rule files.
